Qwen Image Studio 학습 노트

내 컴퓨터(애플 실리콘 맥) 안에서 최신 오픈 이미지 모델 Qwen-Image-2.1을 돌리는 스튜디오입니다. 무엇인지, 어떻게 만들어졌는지, 나에게 필요한지, 스킬로 만들 가치가 있는지를 차례로 정리했습니다.

결론 먼저무엇인가핵심 개념세 가지 실행 경로 코드에서 배울 점나에게 필요한가기대 효과주의할 점 확장·응용스킬화 점검학습 순서

결론 먼저

  • 장비가 결정합니다. 애플 실리콘 맥에 통합 메모리 32GB 이상이 있어야 실용적으로 씁니다. Windows PC나 16GB 맥이라면 지금 설치할 이유가 없습니다.
  • 맞는 장비가 있다면 쓸 만합니다. 장당 비용 0원, 교인 사진 같은 자료를 외부 서버에 올리지 않아도 되는 점, 시드를 바꿔 가며 마음껏 초안을 뽑을 수 있다는 점이 이점입니다. 대신 1024×1024 한 장에 5~11분이 걸립니다.
  • 스킬은 '설치용'으로 만들 필요가 없습니다. 설치는 한 번이고 README 스크립트로 충분합니다. 맞는 맥이 있을 때만, 이미 가진 media-gen-image·webtoon-panel-render에 로컬 초안 엔진을 붙이는 얇은 스킬 하나가 효과가 있습니다.
  • 장비가 없어도 공부할 가치는 있습니다. 대기열 워커, 실시간 진행률(SSE), 엔진 교체 구조는 앞으로 만들 '에이전트 하네스'나 앱에 그대로 가져다 쓸 수 있는 설계입니다.

1. 무엇인가

세 층으로 이루어져 있습니다. 맨 위는 브라우저에서 쓰는 웹 앱(Next.js 16 + shadcn/ui), 가운데는 요청을 한 줄로 세워 하나씩 처리하는 대기열 워커, 맨 아래는 실제 그림을 그리는 엔진 두 가지(ComfyUI + GGUF, 또는 mflux/MLX)입니다.

2026년 9월 20일 공개된 Qwen-Image-2.1(7.1B DiT + Qwen3-VL 8B 텍스트 인코더)을 맥에서 돌리려고 만든 개인 프로젝트이며, 코드 대부분이 Claude Code로 작성된 흔적(web/CLAUDE.md, AGENTS.md)이 있습니다.

2. 먼저 알아야 할 개념 12가지

README를 읽다 막히는 단어들입니다. 이 정도만 알면 설정 화면의 거의 모든 옵션이 읽힙니다.

Diffusion / DiT

잡음을 지워 그림을 만드는 방식

무작위 잡음에서 시작해 '스텝'마다 조금씩 잡음을 걷어 냅니다. DiT는 그 일을 하는 트랜스포머 본체(7.1B)입니다.

Text Encoder

프롬프트를 읽는 부분

Qwen3-VL 8B. 글과 참조 이미지를 이해해 그림 본체에 전달합니다. 메모리를 가장 많이 먹는 부품입니다.

VAE

압축된 그림을 실제 픽셀로

디퓨전은 축소된 '잠재 공간'에서 일하고, 마지막에 VAE가 PNG로 풀어 냅니다(0.7GB).

Quantization

양자화 (Q8, Q4, int8)

가중치 숫자를 16비트에서 8·4비트로 줄여 메모리를 아낍니다. Q8은 품질 손실이 거의 없고, 맥에서는 오히려 Q4보다 빠릅니다.

GGUF

양자화 모델 파일 형식

llama.cpp 진영의 형식. ComfyUI-GGUF 노드가 이를 읽어 ComfyUI에서 씁니다.

Steps

스텝 수

잡음을 걷는 횟수. 권장 40. 시간은 스텝에 정비례, 해상도에는 거의 제곱으로 늘어납니다.

CFG / Guidance

프롬프트를 얼마나 강하게 따를지

기본 1.0. 1보다 크면 부정 프롬프트를 쓸 수 있지만 스텝당 계산이 두 배가 됩니다.

Seed

잡음의 출발점 번호

같은 시드와 설정이면 같은 그림이 나옵니다. "작게 여러 장 → 좋은 시드만 크게"가 핵심 요령입니다.

img2img / Edit

참조 이미지로 만들기

기존 그림을 바탕으로 바꾸거나("배경을 겨울로"), 최대 3장을 참조해 편집합니다.

MPS / MLX

맥 GPU를 쓰는 두 길

MPS는 PyTorch의 맥 GPU 백엔드, MLX는 애플이 만든 전용 프레임워크입니다. 둘 다 NVIDIA 없이 맥 GPU를 씁니다.

ComfyUI

노드 연결식 이미지 도구

부품(로더·샘플러·디코더)을 선으로 이어 '워크플로'를 만듭니다. 화면 없이 API로도 호출됩니다.

SSE

서버가 브라우저로 밀어 주는 알림

Server-Sent Events. 진행률·미리보기를 새로고침 없이 실시간으로 보여 주는 장치입니다.

4. 코드에서 배울 설계 패턴

이미지 모델을 쓰지 않더라도, 아래 일곱 가지는 '오래 걸리는 AI 작업을 사람에게 보여 주는 앱'을 만들 때 그대로 빌려 쓸 수 있는 구조입니다. 파일 경로를 따라 읽어 보면 좋습니다.

패턴어디에무엇을 배우나
직렬 작업 대기열web/src/lib/server/queue.tsGPU처럼 한 번에 하나만 돌릴 수 있는 자원 앞에 줄을 세웁니다. kick()이 다음 작업을 꺼내고, 끝나면 50ms 뒤 스스로 다시 부릅니다. 브라우저를 닫아도 작업이 계속됩니다.
실시간 진행률 (SSE)api/events/route.ts, hooks/use-jobs.ts단계(모델 로딩 → 프롬프트 처리 → 생성 → 디코딩 → 저장), 스텝, 남은 시간, 중간 미리보기를 서버가 밀어 줍니다.
엔진 교체 구조comfy.ts, mflux.ts두 엔진이 같은 모양의 update·onCancelReady 콜백을 받습니다. 워커는 어떤 엔진인지 몰라도 됩니다. 나중에 fal.ai 같은 원격 엔진도 같은 자리에 끼울 수 있습니다.
필요할 때 자동 기동comfy.ts, api/status/startComfyUI가 꺼져 있으면 첫 요청 때 스스로 켭니다. 사용자는 서버 두 개를 신경 쓰지 않아도 됩니다.
멱등 설치 스크립트setup-comfyui.sh이미 된 단계는 건너뜁니다. 몇 번을 다시 실행해도 안전합니다. 다운로드 스크립트는 SHA256과 디스크 여유를 먼저 확인합니다.
남의 코드를 고치지 않고 감싸기custom_nodes/qwen-studio-gguf-qwen3vl/ComfyUI-GGUF가 Qwen3-VL 비전 타워를 못 읽는 문제를, 원본을 수정하지 않고 로더 함수를 감싸 텐서 이름을 바꿔 끼워 해결합니다(정규식 매핑 9줄).
프리셋 설계web/src/lib/presets.ts"초고속 초안 / 빠른 초안 / 표준 / 고해상도 / 저메모리"처럼 사람 말로 된 묶음 뒤에 스텝·해상도·양자화를 숨깁니다. 스킬의 옵션 설계에도 그대로 쓰입니다.

지금 저장소에는 이미 이미지 생성 경로가 둘 있습니다. media-gen-image·media-gen-edit·media-gen-thumbnail은 fal.ai(nano-banana-pro, 유료), webtoon-panel-render는 codex CLI의 이미지 생성을 씁니다. 그러니 질문은 "이미지 생성이 필요한가"가 아니라 "로컬 엔진이 지금 경로보다 나은 순간이 있는가"입니다.

6. 왜 하고, 무엇이 달라지나

왜

지금 파이프라인(웹툰·영상·썸네일)은 '초안을 여러 장 뽑아 고르는' 단계에서 비용과 한도가 가장 많이 나갑니다. 로컬 엔진은 이 탐색 단계를 공짜로 만들어 줍니다. 마음에 드는 구도·시드를 찾은 뒤에만 유료 엔진으로 최종본을 뽑으면 됩니다.

기대 효과

  • 비용: 초안 탐색 비용이 0이 됩니다. 웹툰 한 화 50패널을 서너 번씩 시험하는 경우에 차이가 큽니다.
  • 개인정보: 교인·가족 사진, 내부 행사 사진을 외부 서버에 올리지 않고 편집합니다.
  • 재현성: 같은 시드·설정이면 같은 그림이 나와 시리즈물(주간 묵상 카드 등)의 톤을 고정하기 쉽습니다.
  • 학습: 스텝·CFG·양자화를 직접 만지며 이미지 모델이 어떻게 움직이는지 몸으로 익힙니다. 프롬프트 작성 실력이 유료 엔진에서도 그대로 올라갑니다.

기대하지 말아야 할 것

  • 빠른 대량 생산. 표준 품질 한 장에 5분 이상입니다. 증류(Lightning) LoRA가 공개되면 5~10배 빨라질 수 있지만 아직 없습니다.
  • 한글 글자 렌더링을 믿고 쓰기. Qwen-Image 계열은 영문·중문 글자에 강하다고 알려져 있지만, 한글 간판·자막은 직접 시험해 보고 판단해야 합니다.

7. 주의할 점

Heretic 텍스트 인코더는 쓰지 않기를 권합니다. README의 install-text-encoder-heretic.sh는 원본 인코더가 거부하던 프롬프트를 처리하도록 '거부 반응을 소거한' 파생 모델을 설치합니다. 웹 앱의 '초고속 초안' 프리셋이 설치되어 있으면 이 인코더를 우선 고르게 되어 있습니다(presets.ts의 textEncoder: "heretic"). 사역 자료를 만드는 용도라면 설치하지 말고, 설치했다면 초고속 초안에서도 int8 인코더를 고르세요. 메모리 4GB 절약 외에 얻을 것이 없습니다.
  • Windows 미지원. 스크립트가 zsh와 맥 GPU(MPS/MLX)를 전제로 합니다. NVIDIA GPU가 있는 Windows라면 이 저장소 대신 ComfyUI를 직접 설치하고 같은 GGUF 모델을 받는 편이 맞습니다.
  • 메모리가 진짜 병목. 36GB 장비에서도 브라우저·IDE를 띄워 두면 스왑이 생겨 두 배 가까이 느려집니다. 두 엔진을 동시에 돌리면 둘 다 느려집니다.
  • 갓 나온 프로젝트. 모델 공개(9월 20일) 이틀 뒤 올라온 개인 저장소입니다. 모델·노드 버전이 바뀌면 깨질 수 있습니다.
  • 라이선스 확인. 코드는 MIT지만 ComfyUI는 GPL-3.0, 모델 가중치는 Qwen 라이선스입니다. 교회 출판물·유료 콘텐츠에 쓰기 전에 모델 라이선스를 한 번 읽어 두세요.
  • 백그라운드 잔류. 웹 앱이 켠 ComfyUI는 웹 앱을 꺼도 남습니다. pkill -f "ComfyUI/main.py"로 끕니다.

8. 확장·응용 방법

웹툰 초안 렌더러

webtoon-panel-render 앞단에 붙여, 패널마다 640² 초고속 초안(46초)을 시드 3~4개로 뽑아 구도를 고른 뒤 최종만 codex로 렌더합니다.

설교 슬라이드 배경

16:9 프리셋 + 수채화·영화 장면 스타일로 본문 장면 배경을 만듭니다. 같은 시드를 고정하면 시리즈 설교의 톤이 일정합니다.

주보·SNS 카드

church-social-post, midweek-devotional의 이미지 칸을 로컬로 채웁니다. 글자는 나중에 얹고 배경만 생성하는 방식이 안전합니다.

사진 편집 (외부 전송 없이)

행사 사진의 배경 정리, 계절 바꾸기, 스타일 변환을 참조 이미지 편집으로 처리합니다. 얼굴이 있는 사진은 결과를 꼭 사람이 확인합니다.

성경 장면 일러스트

sermon-history-culture-geo-context로 고증 정보를 먼저 뽑아 프롬프트에 넣습니다(의복·건축·지형). 모델은 기본적으로 '서구 회화풍 성경'을 그리려 하니 구체적으로 지시해야 합니다.

썸네일 대량 시안

media-gen-thumbnail에서 시안 10장은 로컬로, 고른 1장만 nano-banana-pro로 고품질 재생성합니다.

밤새 배치 생성

웹 앱 대기열에 수십 개를 넣어 두고 자면 아침에 갤러리에 쌓여 있습니다. 느린 속도를 시간으로 상쇄하는 방법입니다.

설계 패턴 이식

대기열 + SSE 진행률 + 엔진 교체 구조를 agent-native-app-harness나 영상 파이프라인의 진행 대시보드에 그대로 씁니다.

9. 스킬로 만들 필요가 있는가

후보판정이유

웹 앱 사용법 스킬만들지 않음사람이 브라우저로 쓰는 도구라 Claude가 끼어들 자리가 없습니다.
local-image-qwen (생성 호출 스킬)조건부맥 32GB 이상일 때만. Claude Code가 comfy-generate.py를 불러 초안을 뽑고, 프롬프트 재작성·시드 기록·결과 확인을 맡습니다.
기존 media-gen-image에 로컬 엔진 옵션 추가가장 권장새 스킬을 늘리지 않고, 이미 있는 프롬프트 재작성·비용 확인 흐름에 "엔진: local / fal" 갈래만 더합니다. 231개 스킬을 더 늘리지 않는 쪽이 관리에 낫습니다.

맥이 준비되면 아래 뼈대로 시작하면 됩니다. 실제 파일은 장비를 확인한 뒤에 만드는 것이 맞아 저장소에는 아직 넣지 않았습니다.

## 전제 확인
1. `uname -sm` 이 Darwin arm64 인지, QWEN_ROOT 에 ComfyUI/ 가 있는지 확인. 없으면 중단하고 media-gen-image 로 안내.
2. Heretic 인코더는 쓰지 않는다 (--text-encoder int8 고정).

## 절차
1. 의도 수집 → 영어 프롬프트로 재작성해 사용자에게 보여 준다.
2. 탐색: 640x640, 12스텝, 시드 4개로 초안 생성
   python3 $QWEN_ROOT/comfy-generate.py "<prompt>" --steps 12 --width 640 --height 640 --seed <n> -o outputs/draft_<n>.png
3. 사용자가 고른 시드만 1024² 40스텝으로 재생성 (5~6분 걸린다고 미리 알린다).
4. outputs/seeds.md 에 {프롬프트, 시드, 해상도, 스텝, 파일} 을 기록.
5. 최종본을 유료 엔진으로 원하면 media-gen-image 로 프롬프트와 함께 넘긴다.

10. 학습 순서

  1. 개념 (30분): 위 2장의 12개 개념을 읽고, README의 "속도를 올리는 방법" 표를 다시 봅니다. 스텝·해상도·CFG가 시간에 어떻게 영향을 주는지 말로 설명할 수 있으면 됩니다.
  2. 코드 읽기 (1시간): presets.ts → queue.ts → comfy.ts 순서로 읽습니다. Claude Code에서 저장소를 열고 "queue.ts의 kick이 어떻게 다음 작업을 고르는지 설명해 줘"처럼 파일 하나씩 물어 가며 읽으면 빠릅니다.
  3. 장비 판정: 5장의 자가진단으로 설치 여부를 정합니다. 해당이 없으면 여기서 멈추고 4장의 설계 패턴만 가져가도 충분합니다.
  4. 설치·첫 생성 (맥이 있을 때, 반나절): ./setup-comfyui.sh → ./run-web.sh → '초고속 초안'으로 한 장. 초고속 초안 선택 시 인코더가 Heretic이 아닌지 확인합니다.
  5. 비교 실험: 같은 프롬프트로 로컬 표준 / nano-banana-pro / codex 결과를 나란히 놓고, 내 용도(웹툰·슬라이드·썸네일)에서 차이가 의미 있는지 봅니다. 한글 글자도 이때 시험합니다.
  6. 스킬 연결: 차이가 견딜 만하면 9장의 뼈대로 media-gen-image에 로컬 갈래를 붙입니다.

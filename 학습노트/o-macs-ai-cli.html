O-MACS, AI CLI 네 개를 한 콘솔에서 부리는 법

WAAT(수요일 오후 AI 토크) 마켓에 올라온 「O-MACS · AI-CLI 4종 협업 콘솔」을 정리하고, 231개 스킬을 운영하는 내 작업 방식에 이것이 필요한지 판단한다.

먼저 읽을 것: 확인한 범위

작업 환경의 네트워크 정책이 waat.community 접속을 차단해서 판매 페이지 원문은 열지 못했다. 검색으로 확인된 사실은 다음 세 가지뿐이다.

  • WAAT는 매주 수요일 오후 AI를 주제로 이야기하는 한국어 커뮤니티이고, 사이트 안에 AI 툴 마켓이 있다.
  • 그 마켓에서 O-MACS(오-맥스)를 판매한다.
  • O-MACS는 AI-CLI 4종 협업 콘솔 시스템이며 브라우저와 모바일 앱으로 쓴다.

가격, 정확한 4종 구성, 설치 방식은 확인하지 못했다. 아래에서 "추정"이라고 표시한 부분은 같은 범주의 공개 도구를 근거로 한 설명이다. 원문을 붙여 넣어 주면 이 노트를 사실 기준으로 고쳐 쓰겠다.

1 · 개념

무엇을 하는 물건인가

AI CLI는 터미널에서 돌아가는 코딩·작업 에이전트다. 파일을 읽고 쓰고, 명령을 실행하고, 여러 단계를 스스로 이어 간다. 지금 대표 주자는 넷이다.

CLI만든 곳프로젝트 지침 파일강점(일반적 평가)
Claude CodeAnthropicCLAUDE.md스킬·훅·서브에이전트 생태계, 긴 작업 지휘
Codex CLIOpenAIAGENTS.md코드 구현·리뷰, codex exec 비대화 실행
Gemini CLIGoogleGEMINI.md큰 컨텍스트, 구글 검색 연동
네 번째(추정)미확인—OpenCode·Copilot CLI·Kimi 등이 흔한 후보

각 CLI는 따로 실행하면 서로를 모른다. 협업 콘솔은 이 넷을 한 화면에 띄워 놓고, 한 모델이 쓴 결과를 다른 모델에게 넘기거나 같은 질문을 동시에 던져 비교하게 해 주는 지휘대다. O-MACS는 여기에 브라우저 화면과 모바일 앱을 붙여, 책상에서 떨어져 있어도 진행 상황을 보고 지시할 수 있게 한 것으로 보인다.

같은 범주의 공개 도구

판매 제품의 내부를 볼 수 없으니, 구조가 비슷한 오픈소스로 원리를 익히는 편이 빠르다.

  • claude_codex_bridge (CCB): Codex·Claude·Gemini 등을 한 작업 공간에서 섞어 쓰는 멀티 에이전트 CLI. 안드로이드 모바일 앱과 게이트웨이 포함.
  • claude-squad: 여러 터미널 에이전트를 tmux와 git worktree로 나눠 관리.
  • MobileCLI: 휴대폰에서 Claude Code·Codex·Gemini CLI 조종.
  • agents-council: Claude Code 안에서 Codex·Gemini의 의견을 모으는 플러그인.
2 · 판단

나에게 필요한가

조건부 · 지금 구매는 보류

필요한 기능의 절반 이상은 이미 갖고 있다. 빠진 것은 "다른 회사 모델에게 교차 검증 받기" 하나다.

저장소를 점검한 결과, 협업 콘솔이 주는 기능 대부분이 이미 스킬이나 Claude Code 기본 기능으로 있다.

콘솔이 주는 기능내가 이미 가진 것판정
휴대폰·브라우저에서 원격 지시Claude 앱의 클라우드 세션(claude.ai/code), Remote Control. 지금 이 노트도 그렇게 만들고 있음이미 있음
여러 에이전트 병렬 실행parallel-task, kkirikkiri, harness, Claude Code 서브에이전트이미 있음
Codex에게 일 맡기기pumasi(Codex 병렬 외주), task-orchestrator(tmux+codex)이미 있음
여러 관점의 토론·비판council(인물 페르소나), redteam(목적별 레드팀)같은 모델 안의 페르소나
다른 회사 모델의 독립 검증체계적으로 묶인 스킬 없음빈칸
네 CLI를 한 화면에서 보기없음. 다만 필요한 빈도가 낮음편의 기능

이럴 때는 사는 쪽이 낫다

  • Codex·Gemini 구독을 이미 내고 있고, 매일 둘 이상을 동시에 돌리고 있다.
  • 터미널 창을 여러 개 오가는 일 자체가 하루 30분 이상 새고 있다.
  • 판매자가 한국어 지원과 업데이트를 계속 제공한다(커뮤니티 제품은 이것이 가장 큰 가치다).

이럴 때는 보류가 낫다

  • 주력이 Claude Code이고 다른 CLI는 가끔 쓴다. 지금 내 상태다.
  • 설교·글·문서 작업이 많아, 화면 네 개보다 "작성 → 다른 모델 검증" 한 줄 흐름이 더 쓸모 있다.
3 · 이유와 효과

왜 여러 모델을 함께 쓰는가

얻는 것

  • 편향 상쇄: 같은 모델이 쓰고 같은 모델이 검토하면 같은 맹점을 공유한다. 다른 회사 모델은 다른 데서 틀린다.
  • 사실 검증: 신학 인용, 통계, 법령처럼 틀리면 곤란한 내용을 두 번째 모델이 다시 확인한다.
  • 사용량 분산: 한 구독의 한도에 걸려도 다른 CLI로 일을 이어 간다.
  • 병렬 처리: 조사·작성·검증을 동시에 돌려 대기 시간을 줄인다.

치르는 것

  • 구독료: 모델마다 요금이 붙는다. 네 개를 다 유료로 쓰면 월 비용이 몇 배가 된다.
  • 맥락 불일치: CLAUDE.md, AGENTS.md, GEMINI.md를 따로 관리해야 지침이 어긋나지 않는다.
  • 보안: 원격 콘솔은 내 컴퓨터의 셸을 밖에서 여는 문이다. 인증·접속 범위를 반드시 확인한다.
  • 판단 피로: 답이 넷이면 고르는 일은 결국 내 몫이다.
4 · 확장 응용

내 작업에 붙이면

분야흐름연결할 기존 스킬
설교·강단Claude가 원고 작성 → Gemini가 인용·연대·지명 사실 확인 → Codex가 논리 구조 비판sermon-research, sermon-toego-revision, redteam
영상 제작대본은 Claude, 팩트체크는 Gemini 검색, 자막 타이밍 스크립트는 Codex로 동시에script-writer-factcheck, video-verify
앱 빌드Claude가 계획·감독, Codex가 구현, 다른 모델이 독립 코드 리뷰appbuild-supervisor, pumasi
미래학·비전 코칭같은 시나리오 질문을 세 모델에 던져 서로 다른 동인(driving force) 목록을 합침vision-foresight-scenarios, council
공공 문서한 모델이 공문 초안, 다른 모델이 규정·법령 조항 대조korean-law-search, official-report-skillset
5 · 스킬화 점검

스킬로 만들 필요가 있는가

콘솔 복제는 불필요 · 얇은 교차검증 스킬 하나는 가치 있음

콘솔 전체를 스킬로 흉내 낼 이유는 없다. 화면 관리는 스킬이 할 일이 아니다. 대신 2장의 빈칸, 즉 "Claude가 만든 결과물을 Codex·Gemini에게 비대화 모드로 보내 독립 의견을 받아 합치는" 스킬 하나는 231개 스킬 거의 전부에 꽂아 쓸 수 있다.

만든다면 이런 모양(초안)

---
name: cross-check
description: 완성된 원고·코드·계획을 다른 회사 AI(Codex CLI, Gemini CLI)에게
  비대화 모드로 보내 독립 검토를 받고, 일치점·충돌점·Claude 판단을 표로 합친다.
  "교차검증", "다른 AI한테도 물어봐", "세컨드 오피니언" 요청 시 사용.
---
1. 설치 확인: `which codex gemini` — 없는 CLI는 건너뛰고 알린다(키는 묻지 않음).
2. 검토 요청문 작성: 대상 파일 + 검토 관점(사실/논리/구조) + "칭찬 금지".
3. 병렬 실행:
   codex exec "$(cat prompt.md)"   > review-codex.md
   gemini -p "$(cat prompt.md)"    > review-gemini.md
4. 합치기: 두 모델이 모두 지적 → 반드시 수정 / 한쪽만 지적 → Claude가 근거 확인
5. 결과: 수정 제안 표 + 원문 링크. 자동 수정은 하지 않는다.

기존 suite-runtime-keys 규약(키 하드코딩 금지, 없으면 멈춤)을 그대로 따르면 배포용으로도 안전하다.

6 · 학습 순서

직접 익히는 네 단계

  1. CLI 하나 더 설치해 보기. Codex CLI 또는 Gemini CLI를 설치하고, 지금 쓰는 설교 원고 하나를 gemini -p "이 원고의 사실 오류만 찾아줘"로 검토시킨다.
  2. 지침 파일 맞추기. 내 CLAUDE.md의 핵심 규칙을 AGENTS.md·GEMINI.md에 복사해 세 모델이 같은 원칙으로 일하게 한다.
  3. 수작업 교차검증 3회. 일주일 동안 결과물 세 개를 두 모델에 돌려, 두 번째 모델이 실제로 새로운 오류를 잡는 비율을 기록한다.
  4. 판정. 잡는 비율이 높으면 cross-check 스킬로 자동화하고, 매일 두 개 이상을 동시에 돌리게 되면 그때 O-MACS 같은 콘솔 구매를 검토한다.
7 · 자가 점검

이해했는지 확인하기

같은 모델에게 쓰고 검토까지 시키면 무엇이 문제인가?

학습 데이터와 성향이 같아서 같은 맹점을 공유한다. 틀린 인용을 쓴 모델은 검토할 때도 그 인용을 맞다고 보기 쉽다.

Claude Code, Codex, Gemini CLI가 각각 읽는 지침 파일은?

CLAUDE.md, AGENTS.md, GEMINI.md. 협업 시 세 파일의 규칙을 맞춰 두어야 한다.

원격 콘솔을 쓸 때 가장 먼저 확인할 보안 항목은?

누가 접속할 수 있는지(인증 방식)와 접속하면 무엇을 실행할 수 있는지(셸 권한 범위). 외부에서 내 컴퓨터 터미널을 여는 구조이기 때문이다.

내 저장소에서 협업 콘솔 기능과 겹치는 스킬 세 가지는?

pumasi(Codex 외주), parallel-task·kkirikkiri(병렬 에이전트), council·redteam(다관점 토론) 등.

콘솔 구매를 검토할 신호는?

여러 CLI를 매일 동시에 돌리고, 창 전환 자체가 큰 시간 손실이 될 때.

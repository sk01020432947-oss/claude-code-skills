1. 한 장 요약

핵심 문장: AI에게 일을 시키려고 API나 MCP를 서비스마다 연결할 필요가 없습니다. 내가 이미 로그인해 둔 브라우저 안에 AI를 들여놓으면, AI가 사람처럼 화면을 열고 클릭해 일합니다.

한 줄 판별법: 그 일을 남에게 시키려면 내 계정을 빌려줘야 하는가? 그렇다면 Aside가 맞는 자리입니다. API 키만 주면 되는 일은 기존 자동화 도구(n8n, Zapier 등)가 더 안전하고 쌉니다.
크롬 쿠키·비밀번호 가져오기→읽기 작업으로 신뢰 쌓기→메모리 교정→루틴 예약→Slack·터미널(Claude Code)에서 호출

2. 개념: 왜 "브라우저 안의 AI"인가

방식예로그인된 사이트장단점

Aside는 크로미움 기반이라 겉모습은 크롬과 거의 같습니다. 만든 회사는 샌프란시스코의 At Your Side입니다. 공식 문서는 활용처로 인사(온보딩), 재무(SaaS 갱신, 인보이스), 리서치(출처 수집, 가격 캡처), 영업(CRM 검증), 개발(CI 결과 분류)을 듭니다. 공통점은 "로그인해야 보이는 화면을 여러 개 오가는 일"입니다.

4. Claude Code에 붙이기 (④번 영상 + 연동 가이드)

Claude Code를 주로 쓰신다면 이 장이 가장 실용적입니다. 연결하면 Claude Code가 "로그인해야 보이는 페이지"를 직접 열어 증거를 가져옵니다.

Claude Code (터미널)
   │  MCP
   ▼
aside mcp   ── 도구 2개: exec · repl
   │
   ▼
Aside 브라우저 (내가 로그인해 둔 프로필)
   │
   ▼
YouTube Studio · 교회 행정 포털 · 회원 전용 게시판

설치와 등록 (macOS 기준. 공식 페이지와 대조한 뒤 실행하세요)

# 1) CLI 설치 (앱의 설정 → Developers 메뉴에서도 가능)
curl -fsSL https://releases.aside.com/install.sh | bash
which aside            # 경로가 찍히면 성공

# 2) Claude Code에 MCP 서버로 등록 (모든 프로젝트에서 쓰려면 user 범위)
claude mcp add --scope user aside -- ~/.local/bin/aside mcp
claude mcp list        # aside가 보이면 성공
자주 하는 실수: --scope 같은 Claude Code 플래그는 반드시 -- 앞에 둡니다. 뒤에 두면 aside에 넘어가는 인자가 되어, 범위가 기본값(현재 프로젝트)으로 잡힙니다.

exec와 repl의 구분

도구누가 판단하나언제 쓰나
execAside 에이전트에게 일을 통째로 넘깁니다"결과만 맞으면 된다" (조사, 요약)
repl내가 적은 단계를 그대로 실행합니다"매번 같은 순서로 같은 것을 봐야 한다" (캡처, 내려받기, 정기 점검)
함정: 커뮤니티 기록에 따르면 비대화형으로 실행한 aside exec는 권한 질문을 만나면 호출을 거부하고 종료 코드 0으로 끝날 수 있습니다. 종료 코드 0을 성공으로 믿지 말고, 결과 파일에 기대한 값이 들어 있는지 확인하세요.

실제 사례: 한 국내 사용자는 Claude Code가 Aside를 "인턴처럼" 부리게 해서, 로그인 벽 뒤의 커뮤니티 글 2,428건(1,436명)을 수집해 Git 저장소에 쌓았습니다.

5. 위험과 비용

요금제가격내용
Free0달러월 500 크레딧(매월 1일 초기화), 루틴 3개. 내 구독을 연결하면 무료로도 충분한 경우가 많습니다
Pro월 20달러사용량 3배, 무제한 루틴, Ultrabrowse, Channels, 클라우드 핸드오프. 모델 값이 아니라 기능 값으로 보면 됩니다
Max월 200달러대용량 사용자용

한 실측 후기에서는 Aside 자체 모델로 유튜브 검색 1회에 약 150 크레딧, 네이버 블로그 검색 1회에 약 55 크레딧이 들었습니다. 비용은 결과 개수가 아니라 방문한 페이지 수가 좌우합니다.

  • 프롬프트 인젝션: 남이 쓴 글(커뮤니티, 댓글)에 숨은 지시가 섞여 AI를 조종할 수 있습니다. 남의 글을 모으는 작업은 읽기만 시키고, 그 결과로 무언가를 실행시키지 마세요.
  • 권한 위임: 크롬 쿠키를 가져온다는 것은 모든 로그인 권한을 맡긴다는 뜻입니다. 은행, 교단 행정, 성도 개인정보가 있는 계정은 처음엔 빼 두세요.
  • 경계 행동: 결제, 발송, 게시는 사람 확인을 거치게 설계돼 있지만, 확인 버튼을 습관적으로 누르면 소용이 없습니다. 첫 2주는 읽기와 정리만 맡기세요.
  • 알려진 실패: 보안문자가 있는 로그인(예: 카카오)에서는 자동화가 실패합니다. 아래로 스크롤해야 불러오는 페이지(lazy load)는 아래쪽 내용을 놓칠 수 있습니다. 상대 사이트 장애가 에이전트 실패처럼 보일 때도 있습니다.
  • 신생 제품: 출시된 지 몇 달 안 된 제품입니다. 성능 주장은 중립적인 재현이 나오기 전까지 마케팅으로 보세요.

6. 나에게 필요한가? (이 저장소의 스킬 231개로 본 사용자 프로필 기준)

저장소를 보면 목회와 설교(sermon-*, 주해 파이프라인), 설교 유튜브(sermon-to-youtube, youtube-video-pipeline, media-gen-thumbnail), 앱 개발(appbuild-*), 공공 행정(transport-receipt-collector) 작업을 Claude Code로 하고 계십니다.

영역필요도이유
설교 채널 운영 (YouTube Studio)높음Studio 분석은 API 연결이 번거로운 "로그인 화면" 업무라서 Aside의 정확한 자리입니다(③번 영상의 사례)
Claude Code 리서치 파이프라인높음insane-search, agent-reach가 막히는 로그인 벽(페이스북 그룹, 회원제 카페)을 aside mcp로 넘을 수 있습니다
행정 반복 업무 (영수증, 정산, 포털 신청)중간API 없는 포털에 맞습니다. 다만 보안문자가 있는 사이트는 안 되니 하나씩 확인해야 합니다
앱 개발 QA (appbuild)중간로그인된 상태로 내 앱을 테스트할 수 있습니다(④번 영상의 Playwright 대체)
설교 준비와 주해낮음대화형 사고 작업이라 브라우저 자동화의 이점이 적습니다
결론: 써 볼 가치가 있지만, 주력 브라우저를 바로 바꿀 필요는 없습니다.
① 비용이 0입니다. 무료 플랜에 이미 쓰는 Claude 구독을 연결하면 됩니다.
② "설교 채널 주간 리포트" 한 가지로 2주만 시험해 보세요.
③ 효과가 확인되면 aside mcp를 Claude Code에 붙여 기존 스킬과 연결합니다.
단순히 로그인된 사이트를 한두 번 보는 정도라면, 이미 쓸 수 있는 Claude in Chrome으로 충분합니다.

왜 그렇게 해야 하나, 어떤 효과가 있나

  • 시간이 줄어드는 곳은 세 군데뿐입니다. ① 화면 이동(탭 열기, 로그인, 찾아 들어가기), ② 설명 반복(메모리가 대신 기억), ③ 착수 지연(루틴이 알아서 시작). 그중 ③이 가장 크고, 가장 잘 안 세어집니다.
  • 본전은 2개월 차에 넘습니다. 가이드의 계산 예시로는, 주 2회 25분 걸리던 업무가 6분으로 줄면 월 약 163분을 아낍니다. 처음 익히는 데 약 230분이 드니 첫 달은 손해이고, 2개월 차부터 이익입니다. 실측 전의 가정치입니다.
  • 증빙이 남습니다. 리서치에서는 시간보다, 출처와 캡처가 빠짐없이 남는다는 점이 더 큰 가치일 수 있습니다.

③ 경쟁 채널 썸네일 수집
유사 설교 채널의 최근 썸네일과 제목 패턴을 repl로 매번 같은 방식으로 캡처해 media-gen-thumbnail의 참고 자료로 씁니다.
④ 구독료 점검 (월 1회)
결제 내역 페이지를 모아 "서비스명, 금액, 결제일, 다음 결제일" 표를 만듭니다. 해지는 사람이 합니다.
⑤ 행정 포털 초안 입력
출장·정산 양식의 초안까지만 채우고, 제출은 사람이 누릅니다. "만드는 단계와 제출하는 단계를 분리"하는 원칙입니다.
⑥ 내 앱의 "AI 사용자 테스트"
appbuild로 만든 앱에 로그인한 상태로 핵심 흐름을 수행시킵니다. 에이전트가 헤맨 곳이 곧 UX 결함입니다. 의미 있는 버튼과 레이블, 글자로 된 상태 표시가 있으면 AI도 사람도 덜 헤맵니다.

8. 2주 실천 과제 (하루 10분)

1주차: 되돌릴 수 있는 것만
□ 1일  설치 (크롬 완전 종료 후) + Claude 구독 연결 + 크레딧 잔량 확인
□ 2일  후보 업무 3개 적기 + 각각 지금 걸리는 시간을 스톱워치로 재기
□ 3일  1개 골라 "읽기 작업" 시키기. 출력 형태를 지정 ("4칸 표로")
□ 4일  메모리 파일 열어 틀린 고유명사 고치기
□ 5일  같은 일을 지시문 절반 길이로 다시 시키기
□ 주말  지시문 한 줄로 저장 + 실측 시간 기록

2주차: 자동화와 확장
□ 1일  루틴 걸기. 단 ①두 번 이상 성공 ②실패해도 피해 없음 ③결과 볼 자리 있음을 확인한 뒤
□ 2일  루틴 결과가 도착했는지 확인
□ 3일  Claude Code에서 aside mcp로 한 번 호출해 보기
□ 4~5일  후보 2번 선정과 실측까지만
□ 주말  본전 계산 (투입 시간 vs 절감 시간)
2주 뒤 자기 점검: ① 내가 열지 않아도 결과를 받는가? ② 지시문이 저장돼 있어 남도 그대로 쓸 수 있는가? ③ 줄어든 시간이 실측 숫자로 적혀 있는가? 셋 다 "예"가 아니면 아직 업무에 붙은 것이 아닙니다.

9. 스킬로 만들 필요가 있는가: 점검 결과

후보판정이유
Aside 사용법 스킬❌ 지금은 불필요Aside는 앱이고, 설치와 사용법은 이 노트로 충분합니다. 웹 조작과 수집은 이미 insane-search, agent-reach, Claude in Chrome이 맡고 있습니다.
Aside 연동 업무 스킬
(예: /channel-weekly-report)		△ 2주 시험 후 생성연동 가이드의 원칙대로 "같은 일이 두 번 통하면 스킬로 굳힙니다." 지금 만들면 검증 안 된 절차가 굳어 버립니다. 시험이 끝나면 지시문, 가져올 양, 결과 확인 한 줄을 담은 SKILL.md를 만들어 드리겠습니다.
YouTube 영상 학습 + 적합성 점검 스킬✅ 생성함지금처럼 영상 링크를 주고 "분석 → 학습 정리 → 나에게 필요한가 → 확장 → 스킬화 점검"을 받는 일이 반복되고 있습니다. skills/youtube-study-fit/로 추가했습니다. 로컬 PC에서는 yt-dlp나 insane-search로 자막을 직접 받아 이 노트 형식의 HTML을 만듭니다.
사용법: 로컬 Claude Code에서 /youtube-study-fit <링크1> <링크2>라고 입력하거나, "이 영상 분석해서 나한테 필요한지 정리해 줘"라고 말하면 됩니다. 링크를 여러 개 주면 주제별로 묶어 하나의 노트로 만듭니다.

10. 자기점검 퀴즈 (눌러서 답 보기)

Q1. Aside가 Playwright MCP보다 유리한 결정적 이유는?Playwright는 빈 브라우저를 새로 띄워서 로그인 벽 앞에서 멈춥니다. Aside는 내가 로그인해 둔 세션을 그대로 씁니다(④번 영상).
Q2. 무료로 쓰려면 가장 먼저 무엇을 해야 하나?설정에서 기존 ChatGPT나 Claude 구독을 연결합니다. 크레딧은 Aside 자체 모델을 쓸 때 주로 줄어듭니다.
Q3. 로컬 폴더 권한 3단계와 안전장치는?Read-only, Guard(매번 질문), Full Access. Full Access에서도 삭제 같은 중대 작업 전에는 파이널 컨펌을 받습니다.
Q4. exec와 repl은 각각 언제 쓰나?결과만 맞으면 되는 일은 exec(에이전트에게 위임). 매번 같은 순서로 같은 것을 봐야 하는 일(캡처, 점검)은 repl(내가 적은 단계를 그대로 실행).
Q5. 루틴을 걸기 전에 확인할 세 가지는?① 같은 지시로 두 번 이상 성공했는가 ② 실패해도 피해가 없는가(읽기·초안인가) ③ 결과를 내가 매번 볼 자리가 있는가.
Q6. 커뮤니티 글을 수집할 때의 보안 원칙은?남이 쓴 글에는 프롬프트 인젝션이 섞일 수 있습니다. 결과는 읽기만 하고, 그 결과로 무언가를 실행시키지 않습니다.
Q7. 나에게 가장 먼저 맞는 시험 과제는?설교 채널의 YouTube Studio 주간 지표 요약. 읽기 전용이라 위험이 낮고, API 연결 없이 바로 효과가 보입니다.

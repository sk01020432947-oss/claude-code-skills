# Knowledge Manager 연결 강화 스킬

> 새로 생성된 노트와 기존 vault 노트 간 자동 양방향 링크 생성

## ⚠️ 실행 방법 — 이 절이 아래 본문 전체보다 우선한다

**Phase 1~2(키워드 추출·관련 노트 탐색·점수 계산)는 스크립트가 대신한다.**
본문의 `Obsidian.com` CLI 명령은 전부 무시한다 — 이 PC에 CLI는 없다.

```bash
python "$HOME/.claude/skills/km-link-audit/scripts/vault_graph.py" \
  --vault "/Users/kbg1023/obsidian/Obsidian 2025" --note "기준노트제목"
```

이 한 줄이 돌려주는 것:
- 이 노트가 가리키는 노트 / 이 노트를 가리키는 노트 (이미 이어진 것 — 중복 방지)
- **연결 후보와 사전 점수, 그리고 왜 후보인지의 근거** (키워드·태그·폴더 중 무엇이 겹쳤는지)

**여기서 끝내지 말 것.** 사전 점수는 제목·태그·폴더만 본 것이라
본문이 실제로 관련 있는지는 모른다. 후보 상위 몇 개의 **본문을 Read로 확인**한 뒤
연결할지 정한다. 이 판단이 이 스킬의 핵심이고, 나머지는 스크립트가 한다.

### 이 환경에서 달라지는 것

- **항상 Basic 모드.** 본문의 Standard(Chroma 벡터)·Advanced(Neo4j 그래프) 모드는
  해당 DB가 없어 작동하지 않는다. 의미는 통하지만 표현이 다른 노트
  (예: "회개" ↔ "돌이킴")는 못 찾는다. 그건 사람이 지정해야 한다.
- **자동 실행 안 함.** `km-workflow.md`가 없으므로 노트 생성 후 자동 호출되지 않는다.
  사용자가 요청할 때만 실행한다.
- **볼트 경로**: `/Users/kbg1023/obsidian/Obsidian 2025` (주 볼트, 노트 7,028개).

## 스킬 개요

이 스킬은 노트 생성 후 자동으로 실행되어:
1. 새 노트의 핵심 개념 추출
2. Vault 전체에서 관련 노트 탐색
3. 새 노트에 관련 노트 링크 추가
4. 관련 노트에 역방향 링크 추가 (양방향)
5. 연결 결과 보고

## Phase 1~2 · 스크립트가 대신한다

위 명령 한 줄이 키워드 추출·탐색·점수 계산을 끝낸다. 아래는 스크립트가 쓰는 기준이다.

**제목 키워드**: 공백·하이픈·언더바·괄호로 쪼개고, 날짜(숫자만)와 불용어
(무제·untitled·노트·정리·메모·자료·내용·관련·복사본)와 한 글자는 버린다.

**사전 점수** — 키워드나 태그가 하나도 안 겹치면 후보에 넣지 않는다.
같은 폴더라는 사실만으로는 아무 뜻이 없기 때문이다:

| 배점 | 조건 |
|-----|------|
| +3 | 제목 키워드 겹침 |
| +2 | 태그 겹침 |
| +2 | 같은 폴더 (단독으로는 후보가 되지 못함) |

이미 이어진 노트는 후보에서 자동 제외되므로 중복 링크를 만들 걱정은 없다.

> **사전 점수는 후보를 좁히는 도구일 뿐 연결 근거가 아니다.**
> 7점짜리 후보라도 본문이 무관하면 잇지 않는다. 반대로 3점이라도 본문이 통하면 잇는다.
> 이 볼트에서 실제로 확인된 예: 같은 본문의 설교 준비 단계 노트 7개가 서로 7점으로 잡혔고
> 이것은 실제로 이어야 할 관계였다. 반면 제목이 '무제 8' 같은 노트는 신호가 없어 후보에서 빠진다.

## Phase 3: 양방향 링크 생성

**두 파일을 모두 고친다.** 기준 노트에 링크를 넣고 상대 노트에도 역방향 링크를 넣는다.
한쪽만 걸면 그래프가 단방향으로 남아 다음 감사에서 다시 잡힌다.
도구는 **Read → Edit**. CLI도 MCP도 이 환경엔 없다.

### 3.1 넣기 전 확인

1. 상대 노트를 Read로 연다.
2. `[[기준노트제목` 이 이미 있으면 **건너뛴다.** (스크립트가 걸러 주지만 최종 확인)
3. `## 관련 노트` 섹션이 있는지 본다.

### 3.2 삽입 위치

| 상황 | 처리 |
|------|------|
| `## 관련 노트` 섹션 있음 | 그 목록 끝에 한 줄 추가 |
| 없음 | 본문 맨 끝(출처·태그 블록이 있으면 그 앞)에 섹션째 새로 만든다 |

```markdown
## 관련 노트

- [[상대노트]] — 같은 본문의 다음 준비 단계
```

**연결 이유를 반드시 적는다.** 이유 없는 링크는 나중에 왜 걸었는지 알 수 없어
"연결은 있는데 쓸모없는" 상태가 된다. "자동 연결"은 이유가 아니다.
스크립트가 준 근거(키워드·태그 겹침)를 그대로 옮기지 말고, 본문을 읽고 확인한 관계를 쓴다.

### 3.3 되돌리기

Edit 한 건씩 들어가므로 잘못 넣었으면 그 줄만 지우면 된다.
**한 번에 5개 노트를 넘기지 않는다** — 되돌릴 수 있는 크기로 유지한다.

## Phase 4: 결과 보고

### 보고 형식

```markdown
## 연결 강화 결과

기준 노트: [[01_본문만남_2026-06-18_로마서1_1-3]]
위치: 1004. sermon/로마서1_1-3/

### 추가한 연결 (양방향)

| 상대 노트 | 사전점수 | 본문 확인 후 판단한 관계 |
|-----------|---------|------------------------|
| [[02_동행일지_2026-06-18_로마서1_1-3]] | 7점 | 같은 본문의 다음 준비 단계 |
| [[03_청중만남_2026-06-18_로마서1_1-3]] | 7점 | 같은 본문, 청중 분석 단계 |

### 통계
- 후보: 6개 · 본문 확인: 6개 · 연결: 2개 · 이미 연결됨: 0개
- 넣지 않은 이유: 나머지 4개는 아직 작성 중이라 링크할 내용이 없음
```

> **연결하지 않은 후보와 그 이유도 함께 보고한다.** 무엇을 걸렀는지 보여야
> 판단이 옳았는지 사용자가 확인할 수 있다.

## 설정 옵션

설정 파일은 없다. 지킬 것은 두 가지뿐이다.

| 규칙 | 값 | 이유 |
|------|-----|------|
| 한 번에 거는 링크 | **5개 이하** | 되돌릴 수 있는 크기 |
| 한 노트의 `## 관련 노트` 링크 | **5개 이하** | 그래프 과밀 방지. 이미 5개면 새 링크를 더하지 말고, 더 관련 깊은 것으로 교체할지 사용자에게 묻는다 |
| 양방향 | **항상** | 한쪽만 걸면 단방향으로 남는다 |

검색 범위를 좁히려면 스크립트의 `--exclude`를 쓴다.

## 수동 실행

노트 생성 없이 기존 노트 연결 강화 시:

```
사용자: "이 노트 연결 강화해줘: [[노트이름]]"
또는: "[[노트이름]] 관련 노트 찾아줘"

→ Phase 1부터 시작하여 해당 노트의 연결 강화
```

### 배치 모드

```
사용자: "Zettelkasten 폴더 전체 연결 강화해줘"

→ 실행 전 대상 폴더 백업 (아래 참조)
→ 폴더 내 모든 노트에 대해 연결 강화 실행
→ 진행률 보고
→ 최종 통계 제공
```

**배치 모드는 실행 전 백업이 필수다.** 단건 Edit은 그 줄만 지우면 되돌려지지만,
여러 노트를 한 번에 고친 뒤에는 어디를 고쳤는지 기억에 의존하게 된다.
볼트가 git이면 커밋 한 번, 아니면 대상 폴더를 복사해 둔다:

```bash
cp -r "/Users/kbg1023/obsidian/Obsidian 2025/{대상폴더}" \
      "/Users/kbg1023/obsidian/Obsidian 2025/_backup/{대상폴더}-$(date +%Y%m%d)"
```

## 에러 처리

| 에러 유형 | 대응 |
|----------|------|
| 검색 결과 없음 | 쿼리 확장 시도 → "고유한 주제" 보고 |
| 노트 업데이트 실패 | 재시도 → 수동 추가 안내 |
| 관련 노트 0개 | "독립적 주제로 판단됨" 보고 |
| 중복 링크 감지 | 스킵 후 보고 |

## 이 스킬을 부르기 좋은 때

`km-link-audit`이 고아 노트를 뽑아 준 직후가 가장 자연스럽다.
감사가 "무엇을 이을지"를 주고, 이 스킬이 "잇는다".

```
km-link-audit 실행 → 고아·연결부족 목록
   → 그중 5개 이하 선택
   → 이 스킬로 --note 조회 → 본문 확인 → Edit 삽입
   → (다음 감사에서 개선 확인)
```

| 링크 삽입 | Edit |

CLI·MCP 계층은 이 환경에 없다. 위 세 가지가 전부다.

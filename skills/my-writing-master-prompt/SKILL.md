# 나만의 글쓰기 마스터 프롬프트 (역설계)

> 출처: 우석지니, 「AI가 나처럼 글을 쓰는 마스터 프롬프트 역설계 (제안서, 보고서, 발표 문장 지침 생성법)」

## 핵심 철학

- **지침을 사람이 쓰지 말고, AI가 역설계하게 하라.** "간결하게 써", "개조식으로 해" 같은 추상적 지침은 AI가 계속 이탈한다. 대신 **AI 원본 문장 ↔ 사용자 수정 문장** 쌍을 AI에게 주고 차이를 분석시켜, 재사용 가능한 구체적 규칙을 도출한다.
- **사용자는 자기 문체의 패턴을 스스로 모른다.** "이게 좋다"는 감각은 있지만 그 규칙은 복잡해서 못 짚는다. 분석은 AI가 잘하는 영역이므로 AI에게 맡긴다.
- **전제 조건: 사용자의 수정 능력.** AI 초안을 보고 "이건 틀렸다"고 판단해 스스로 고칠 수 있어야 이 방법이 작동한다. AI는 사용자의 문장을 따라갈 뿐이다.

## 파일 구조 (이 스킬 폴더 안에 축적)

- `MASTER-PROMPT.md` — 완성/갱신 중인 마스터 프롬프트. **적용 모드에서 항상 이 파일을 먼저 읽는다.**
- `COPY-PROMPTS.md` — 타 AI(챗GPT·제미나이 등)에 붙여넣을 수 있는 복사용 프롬프트 5종. 사용자가 "복사용 프롬프트 줘"라고 하면 이 파일을 제시.
- `data/samples.md` — 수집된 원본↔수정본 쌍. 유형별로 누적.
- `data/rules-log.md` — 분석에서 도출된 규칙의 이력 (선택).

파일이 없으면 첫 수집 때 만든다.

## 5가지 대표 문장 유형

제안서·보고서·발표에 공통 적용:

1. **헤드라인 제목**
2. **핵심 문구** (제목 밑 한두 줄)
3. **거버닝 메시지**
4. **본문 소제목**
5. **본문 내용** — 서술형 / 개조식

유형별로 최소 5개, 가능하면 10개의 쌍이 있어야 규칙의 밀도가 나온다. 1~2개로는 어긋난다.

## 3단계 워크플로

### 1단계 — 샘플 수집 (수집 모드)

사용자가 "AI 원본 + 내 수정본" 쌍을 주면:
- 문장 유형을 판별해 `data/samples.md`에 아래 형식으로 누적한다.

```markdown
## [유형: 제목 | 핵심문구 | 거버닝 | 소제목 | 서술형 | 개조식] — [문서종류: 제안서/보고서/발표] (YYYY-MM-DD)
- 원본: ...
- 수정: ...
```

- 유형별 누적 개수를 알려주고, 5개 미만인 유형은 샘플이 더 필요하다고 안내한다.

### 2단계 — 비교 분석·규칙 도출 (분석 모드)

쌍이 모이면 (또는 사용자가 요청하면) 다음 5개 축으로 차이를 분석한다:

1. **순서** — 문장 구성 순서가 어떻게 바뀌었나
2. **문장 구조** — 만연체→단문, 병렬→분리 등
3. **어휘·종결형** — 어떤 어휘/종결형을 쓰고, 왜 바뀌었나
4. **삭제·추가 패턴** — 반복적으로 지워지거나 더해지는 표현
5. **정보 배치** — 결론이 앞인가 뒤인가, 근거는 어디에 놓이나

도출한 규칙은 **재사용 가능한 구체적 지침**으로 쓴다. "간결하게" 같은 추상 표현 금지 — "형용사·부사를 빼고 수치와 결론을 넣어라", "개조식은 마침표 없이, 서술형 끝에만 마침표" 수준으로.

규칙 도출 후 **그 규칙으로 샘플 문장을 하나 써서 사용자에게 검증받는다.** 사용자가 또 고치면 그 수정이 새 샘플이 된다 (반복할수록 밀도 상승).

### 3단계 — 마스터 프롬프트 생성·갱신 (생성 모드)

도출된 규칙을 `MASTER-PROMPT.md`에 다음 구성으로 정리한다:

```markdown
# 마스터 프롬프트 — [사용자 이름]의 문장 지침

## 1. 문장 구조·종결형 규칙
## 2. 절대 금지 표현
## 3. 제목·소제목 규칙
## 4. 거버닝 메시지 규칙
## 5. 본문 규칙 (서술형 / 개조식)
## 6. 출력 전 자가 점검 체크리스트
## 7. 개인 보정 영역
(예: m-대시 → 쉼표/콜론으로 치환, 시그니처 표현 교정 등 — 사용 중 발견될 때마다 추가)
```

기존 파일이 있으면 덮어쓰지 말고 규칙을 병합·갱신한다. 충돌하는 규칙은 사용자에게 확인.

## 적용 모드

마스터 프롬프트가 존재하는 상태에서 제안서/보고서/발표 문장 작성·수정을 요청받으면:
1. `MASTER-PROMPT.md`를 읽는다.
2. 그 규칙대로 작성한다.
3. 출력 전 자가 점검 체크리스트를 통과시킨다.
4. 사용자가 결과를 고치면 → 그 수정을 새 샘플로 수집 제안 (선순환).

## 시작 규칙 (Starter Rules)

사용자 샘플이 아직 없을 때의 기본값. 강의에서 도출된 규칙으로, 사용자 데이터가 쌓이면 사용자 규칙이 우선한다.

### 공통
- 최상급·추상 수식어 전면 삭제: "최적의", "종합적", "체계적", "다양한", "여러 가지", "혁신적", "궁극적으로"
- "얼마나/어떻게"류 모호한 표현 → 전부 수치로 치환
- 접속어 연쇄 금지 ("~하며, ~하고, ~함으로써") — 문장당 1개까지
- 결론을 문장 앞에 배치, 부연은 괄호나 쉼표로
- 1문장 1메시지, 최대 2문장
- 개조식은 마침표 없이 / 서술형 끝에만 마침표
- 필요시 화살표(→) 등 특수문자 허용

### 제목
- 구성 = 핵심 수단 + 핵심 결과 수치 (예: "업무 처리 시간을 40% 단축하는 AI 기반 통합 플랫폼 구축")
- 보고서 제목은 보고 대상/기간 + 핵심 결과 수치를 앞에 (예: "3분기 운영 현황 보고, 처리 지연 32% 개선")

### 거버닝 메시지
- 제안서: **현재 문제·상태 → 핵심 해결 방안 → 정량 결과** 3단 구조
- 보고서: 전기 현황 수치 1문장 + 핵심 조치 1문장 + 금기(今期) 결과 수치 1문장, 총 2~3문장. 숫자로 출발, Before→After 대비
- 현황·문제 제기 없는 자기주장형 선언으로 시작하지 않는다

### 소제목
- 구체적 조치 + 변경 사항 + 현재 상태, 명사형 종결 (예: "승인 단계 3→2단계 전환 현황")

### 본문 서술형
- 상황 보고: **현황 → 원인 → 메커니즘 → 영향 → 결과**
- 문제 해결 보고: **문제 → 해결책 → 결과 → 효과**
- 현황 서술에는 구체적 근거를 최소 1개 포함

### 본문 개조식
- 구성 = 구체적 주체/대상 + 조치 + 수치 결과 (예: "3자 협의체 구성 → 월 1회 정기 협의", "인력 12명 중 2명 데이터 연계 전담 배치")

## AI 모델 간 편차 관리

- 같은 계열 모델 간(예: Claude 내부)에는 마스터 프롬프트가 거의 그대로 작동한다.
- 타사 모델로 옮길 때는: 마스터 프롬프트로 **샘플을 먼저 생성 → 결과를 보고 프롬프트를 수정 → 수정본을 실사용**하는 보정 사이클을 거친다.

## 코칭 톤

- 사용자의 수정본에서 사용자 자신도 몰랐던 패턴(예: 3단 구조)을 발견하면 명시적으로 짚어준다.
- 규칙은 항상 "원본 → 수정 → 도출 규칙" 근거와 함께 제시한다.
- 문장 수정 능력 자체가 이 시스템의 엔진임을 상기시키되, 훈계하지 않는다.

# 묵은 메모 일괄 정리 (legacy triage)

출처: 문코생 「클로드 코드로 메모 1만 개 자동 분류」(2026-04-14) — 분류 기준을 사람이 먼저 정하지 않고, LLM이 읽고 기준을 제안하게 한다. 이 볼트에서는 **제안까지만 AI, 확정은 사람**(폐쇄 목록 원칙)으로 바꿔 쓴다.

## 0. 스캔 (읽기 전용, 3초)
```bash
python3 ~/.claude/skills/pkm-os/scripts/legacy_scan.py "<폴더>" "<정본폴더>/스캔결과.csv" --exclude PKM _archive _agent-drafts LLM-Wiki
```
규모·정확 중복(본문 공백 무시 해시)·열린 체크박스·바람 표현을 센다. 파일은 건드리지 않는다.
주의: 볼트 이전 때문에 파일 생성일은 2025·2026으로 몰린다. 연도는 프론트매터 `date created`만 믿는다.
주의: 열린 체크박스 대부분은 **클리핑한 강의의 단계 목록**이다(2026-10-09 스캔: 2,302개 중 상위가 수노·Claude Code 강의 노트). 할 일 추출은 내 손 메모(`00. Inbox`·`1004. sermon`·`900. Divisions`·데일리)로 범위를 좁힌다.

## 1. 창발 분류 제안 (폴더당 표본)
폴더별로 제목 전체 + 본문 앞 5줄 표본(최대 200개)을 읽히고:
```
이 노트들을 읽고 의미 있는 카테고리를 제안해 줘. 중복 주제는 합치고, 노트 5개 이하 카테고리는 만들지 마.
각 카테고리에 대표 노트 3개와 노트 수 추정을 붙이고, `02 나의 핵심 맥락` §6 domain 중 어디에 대응하는지 적어.
대응 없는 카테고리는 '목록 밖 후보'로 따로 모아.
```
→ 결과는 `_agent-drafts/`에 표로. **domain 목록 변경은 사람이 결정**한다(PKM/CLAUDE.md 절대 규칙 6).

## 2. 태깅·중복 (승인 후)
- 승인된 분류로 프론트매터 `domain`/`tags` 제안 CSV를 먼저 만들고 사람 확인 → 일괄 적용은 `km-archive-reorganization` R4 규칙(백업·이동 계획 승인·삭제 금지).
- 중복: 스캔 CSV의 `dup_group`(정확 중복) → 대표 1개만 남기고 나머지는 `_archive/`로 이동 제안. 제목만 다른 근사 중복은 LLM에 그룹별로 판정시킨다.

## 3. 연결
- 같은 주제 노트끼리 MOC·위키링크는 `km-link-strengthening`. 그래프 뷰는 결과 확인용이지 목적이 아니다(`2026-09-13 그래프 뷰 전에 할 일 (구요한)` 소스 노트).

## 4. 행동으로 (할 일 → 캘린더)
- 범위를 좁힌 폴더에서 "언젠가 할 일"을 뽑아 표(노트 링크·원문 한 줄·추정 소요·우선순위)로 보여 준다.
- 사용자가 고른 것만 Google Calendar 커넥터로 등록한다. **일정 등록은 건별 확인**(외부 쓰기).

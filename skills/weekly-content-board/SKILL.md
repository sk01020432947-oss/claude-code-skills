# Weekly Content Board

콘텐츠를 "생성"하는 게 아니라 "이번 주에 뭘 만들지 결정"하는 회의를 자동화한다.
결과물은 승인 후 직원/외주에게 그대로 넘길 수 있는 HTML 보고서 1장.

핵심 주장: 사장님이 할 일은 글쓰기가 아니라 의사결정이다. AI가 후보를 뽑고 근거를 대면, 사람은 승인만 한다.

## 언제 쓰나

사용자가 이 스킬을 부른 것 자체가 Workflow 도구(다이나믹 워크플로우) 사용에 대한 명시적 동의다.
확인 질문 없이 바로 진행한다.

## Step 1 — 인풋 문서 확보 (Single Source of Truth)

출력이 뒤죽박죽 안 되려면, 가격·경쟁사·고객 목소리 같은 핵심 사실을 **한 곳에만** 적고 모든 단계가 그걸 참조하게 해야 한다. 문서를 여러 개로 쪼개서 각각 따로 채우면 숫자가 어긋난다 (한쪽은 12만원, 다른 쪽은 15만원).

이미 브리프 문서가 있으면 그걸 쓰고, 없으면 대화(인터뷰)로 채운다. 최소 항목:

- **사업 정체성**: 무엇을 파는지, 대표 프로필/페르소나, 톤
- **오퍼**: 가격, 무료 체험/상담 여부, 전환 유도 포인트
- **고객 목소리**: 실제 문의/불만 (있으면 최고의 콘텐츠 소스 — 없으면 웹서치로 보완)
- **경쟁사**: 누가 뭘 하고 있는지
- **금지 표현 / 승인된 표현 목록**: 특히 의료·금융처럼 법적 리스크가 있는 업종은 필수
- **채널**: 이번 주 다룰 채널(블로그/쇼츠/유튜브/카카오 등)과 각 채널 제약

얕게 적어도 된다 — 부족한 부분은 Step 2에서 인터뷰로 메운다. 단, 정보가 세세할수록 결과물도 세세해진다 (실측: 8줄짜리 인풋보다 상세 인풋이 톤·전략·리스크 판단 전부 더 정교했음).

## Step 2 — 오케스트레이션 규칙 확인

Workflow 도구는 이미 다음을 강제한다 (재구현 불필요):
- 서브에이전트는 서로 호출 못 함 — 헤드(이 스킬을 실행하는 나)만 조정한다
- `pipeline()`으로 단계 간 병목 없이 흐르게, `parallel()`은 정말 전체 결과가 동시에 필요할 때만

프로젝트에 `CLAUDE.md`가 있다면 "네스티드 서브에이전트 금지", "모든 단계는 동일 인풋 문서를 참조" 같은 규칙을 적어두면 이후 실행에도 계속 적용된다. 없어도 이 스킬 안에서 지키면 된다.

## Step 3 — 모델 등급 나누기

전 구간에 비싼 모델 쓰지 않는다. 추론이 필요 없는 단순 분류/정리는 싼 모델, 판단이 필요한 곳만 비싼 모델.

| 단계 | 작업 | effort/model |
|---|---|---|
| 입력 검증 | 문서 누락 체크 | low |
| 병렬 분석 | 고객 목소리·경쟁사·오퍼 분석 | low~medium |
| 점수화·우선순위 | 후보 콘텐츠 스코어링 | medium |
| 콘텐츠 브리프 생성 | 채널별 대본/제목/썸네일 카피 | medium~high |
| 리스크 검수 | 법적/의료/금융 표현 검토 | high |
| 최종 종합 | 대표 승인용 HTML 요약 | high |

## Step 4 — Workflow 실행

`Workflow` 도구로 아래 골격을 돌린다. 실제 인풋 문서 내용에 맞춰 프롬프트를 채운다.

```js
export const meta = {
  name: 'weekly-content-board',
  description: '이번 주 콘텐츠 우선순위를 정하는 의사결정 보고서 생성',
  phases: [
    { title: '입력 검증' },
    { title: '병렬 분석' },
    { title: '우선순위 스코어링' },
    { title: '채널별 브리프 생성' },
    { title: '리스크 검수' },
  ],
}

phase('입력 검증')
const brief = await agent('인풋 문서(사업 정체성/오퍼/고객목소리/경쟁사/금지표현)를 읽고 누락·모순된 사실을 표시해라.', { effort: 'low' })

phase('병렬 분석')
const [voice, competitors, offers] = await parallel([
  () => agent('고객 목소리에서 반복되는 문제/불만 3~5개를 뽑아라.', { effort: 'low' }),
  () => agent('경쟁사가 다루지 않는 빈틈을 찾아라.', { effort: 'low' }),
  () => agent('현재 오퍼(가격/무료상담 등)를 콘텐츠 훅으로 정리해라.', { effort: 'low' }),
])

phase('우선순위 스코어링')
const ranked = await agent(
  `다음 근거로 이번 주 콘텐츠 후보에 점수를 매기고 상위 1~3개를 선정해라: ${JSON.stringify({ voice, competitors, offers })}`,
  { effort: 'medium' }
)

phase('채널별 브리프 생성')
const briefs = await pipeline(
  ranked.candidates,
  c => agent(`"${c.title}" 후보로 블로그/쇼츠/유튜브 각 채널 대본·제목·썸네일 문구를 써라. 금지 표현 목록을 반드시 지켜라.`, { effort: 'medium' })
)

phase('리스크 검수')
const reviewed = await parallel(briefs.map(b => () =>
  agent(`다음 콘텐츠에 법적/의료/과장광고 리스크가 있는지 검토해라: ${JSON.stringify(b)}`, { effort: 'high' })
))

return { brief, ranked, briefs, reviewed }
```

## Step 5 — 출력: 승인용 HTML 1장

Workflow 결과를 받으면 Artifact 도구로 HTML 보고서를 만든다. 필수 섹션:

1. **이번 주 우선순위 콘텐츠** (선정 근거 포함 — "왜 이걸 뽑았는지"가 없으면 대표가 못 믿는다)
2. **채널별 기획** (제목/훅/대본 요지/썸네일 문구) — 그대로 편집자·외주에게 넘길 수 있는 수준
3. **업무 지시서** (유튜브 편집자/블로그 외주/쇼츠 편집자별로 뭘 시킬지)
4. **리스크 검수** (법적/의료/과장광고 — 승인 전 반드시 확인)
5. **승인 체크리스트** (대표가 체크만 하면 끝)

카피라이팅이 AI 티가 나는 건 정상이다 — 이건 내부 결재용 문서지 최종 발행물이 아니다. 표현은 담당자가 다듬는다.

## Step 6 — 재사용

한 번 검증되면 이 스킬 자체가 매주 반복 가능한 자산이다. 다음 주는:
- 인풋 문서의 고객 목소리/후보 목록만 갱신
- 이전 회차 결과물은 삭제하고 다시 실행

## 하지 않는 것

- 콘텐츠 완성본을 직접 만들지 않는다 (그건 편집자/작가의 일)
- 법적 리스크 검수 결과를 최종 승인으로 취급하지 않는다 — 사람이 승인해야 발행
- 여러 인풋 문서를 따로따로 채우지 않는다 — 항상 한 세션에서 함께 채워 사실 불일치를 막는다

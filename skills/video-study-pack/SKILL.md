# video-study-pack — 영상 한 편 → 연구·강의 패키지

원형: 2026-10-06 「병목은 사람, 이해가 병목이다」(안상현, 티타임즈TV) 작업. 결과물 예시는 `~/Desktop/cysjavis/강의_발표/이해가_병목이다_AI시대_리더십/` — 형식이 헷갈리면 그 폴더의 파일을 본다.

## 0. 시작 전 (한 번만 묻는다)
- URL이 없으면 묻는다. 여러 개면 영상마다 이 파이프라인을 따로 돌린다.
- **강의안이 산출물에 있으면 `awesome-ai-motion` 사용 여부를 묻는다**(CLAUDE.md 규칙 8 — 이전 답을 일반화하지 않는다. 같은 요청 메시지에서 이미 답했으면 다시 묻지 않는다). 거절이면 정적 HTML.
- 그 밖에는 중간에 "계속?"을 묻지 않는다(규칙 3). 산출물 범위를 사용자가 줄이면 그 범위만 한다.

## 1. 자막 확보
1. `watch` 스킬로 `--detail transcript` 실행(메타데이터·챕터·설명 확보).
2. 자막이 429 등으로 실패하면 바로 재시도:
   `yt-dlp --skip-download --write-auto-subs --sub-langs "ko-orig,ko,en" --sub-format vtt -o sub "<URL>"`
3. 그래도 없으면 로컬 Whisper: `whisper-cli -m ~/Desktop/cysjavis/KBG-Bible-Labs-Sermon/data/models/ggml-large-v3-turbo-q8_0.bin -l ko -f <16kHz wav>` (오디오는 watch 작업폴더의 다운로드를 `ffmpeg -ac 1 -ar 16000`으로 변환).
4. `python3 scripts/vtt2txt.py sub.ko-orig.vtt 영상자막_<인물>_<채널>.txt` → 전문을 Read로 끝까지 읽는다.
5. 끝나면 watch 작업폴더 삭제.

## 2. 정본 폴더와 공통골격
- 정본: `~/Desktop/cysjavis/<주제폴더>/<한글_제목_폴더>/` (규칙 4, 한글 경로는 python3로 다룬다). 주제폴더는 기존 것 중 고른다(강의_발표·설교연구·AI동향_검토 등).
- 사용자 맥락을 읽는다: `~/obsidian/Obsidian 2025/PKM/02 나의 핵심 맥락.md`.
- `_공통골격.md`를 쓴다 — 형식은 `references/common-skeleton-template.md`. 핵심 N개(타임스탬프), 확장 테제 5~7개, **검증된 참고문헌 목록**(확신하는 서지만, 영상 속 재인용은 "1차 출처 미확인"), 사용자 맥락.
- 법령·통계를 인용할 테제가 있으면 이 단계에서 1차 출처로 확인한다(법령은 korean-law MCP `get_law_text`). 2026-10-06 작업에서 「개인정보 보호법」 제23조를 '종교'로 잘못 적었다가 조문('사상ㆍ신념')으로 고친 전례가 있다.

## 3. 병렬 생산 (백그라운드 에이전트 3 + 본인 1)
`references/agent-prompts.md`의 세 프롬프트를 채워 general-purpose 에이전트 3개를 한 메시지로 띄운다. 그동안 본인은 응용가이드를 쓴다.

| 산출물 | 담당 | 파일 |
|---|---|---|
| 응용가이드 HTML | 본인 | `영상정리_응용가이드.html` — 요약(타임스탬프)·응용확장 표·구체 사례·**사용자 맞춤 실례 5~6개(복붙 가능한 프롬프트 포함)**·추가 자료·스킬 점검표·산출물 표 |
| 논고 | 에이전트 A | `논고_<제목>.md` (APA, 12~16천자 공백 제외) |
| 소책자 | 에이전트 B | `소책자_<제목>.html` (A5 인쇄, 24~32쪽) |
| 강의안 | 에이전트 C | `강의안_<제목>.html` (120/90분, 32~40장, ←/→, N 노트) |

에이전트 보고를 받으면 참고문헌이 골격 목록 안에 있는지, 이상한 단정이 없는지 훑는다.

## 4. 스킬화 점검 (규칙 7)
영상의 방법론이 재사용 가치가 있으면: 설치된 스킬 중 겹치는 것을 먼저 찾고(`ls ~/.claude/skills`, 관련 SKILL.md 서두), 겹치면 **기존 스킬에 모드·reference 추가**(원본 백업을 정본 폴더에), 안 겹칠 때만 새 스킬. 결과는 응용가이드 §스킬 점검 표에 쓴다.

## 5. 옵시디언 저장 (PKM 규칙 — `PKM/CLAUDE.md`를 먼저 읽는다)
- `10 raw/`에는 쓰지 않는다 → 자막은 `00 inbox/YYYY-MM-DD <제목> 자막 (<채널>).md` (프론트매터 status: inbox, why/use_for 채움) + 사용자에게 raw 이동 요청.
- `20 wiki/소스/YYYY-MM-DD <제목> (<인물>).md` — 요약·핵심 주장·직접 인용 3개 이내·내 관점·origin.
- 개념 2~4개(`20 wiki/개념/`), 인물 1개(`20 wiki/인물/`). 기존 노트가 있으면 덮지 않고 `> [!ai]` 콜아웃으로 덧붙인다.
- 프론트매터 7속성 + `domain`·`theology`는 `02 나의 핵심 맥락` §6 폐쇄 목록 값만.
- `index.md` 해당 섹션에 한 줄씩, `log.md`에 날짜 블록, 관련 MOC에 `> [!ai]` 링크.
- `30 output/<강의|설교>/<제목>/`에 허브 노트(`status: draft`) + 논고 md(프론트매터 추가) + HTML 사본.

## 6. 웹 발행 (artifact-design 스킬을 먼저 로드)
절차는 `references/web-publish.md`. 요약: 남이 쓴 HTML은 끝까지 Read → `scripts/webcopy.py`로 `_웹발행/` 사본 → 논고는 pandoc으로 HTML 페이지 → 논고·소책자·강의안 먼저 발행 → 응용가이드의 산출물 표를 아티팩트 URL로 바꿔 마지막에 발행. URL은 허브 노트와 메모리에 기록하고, 재발행 때는 같은 파일 경로(다른 대화에서는 `url`)로 올린다(규칙 1).

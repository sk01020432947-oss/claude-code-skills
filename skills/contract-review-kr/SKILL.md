# 계약서 검토 (contract-review-kr)

법률 의견서가 아니다. 결과물 첫 줄에 "AI 검토 초안 — 최종 판단은 전문가 확인"을 넣는다.

## 1. 먼저 묻는다 (AskUserQuestion 1회, 한 번에 3문항)

- 내 위치: 갑(발주·위촉하는 쪽) / 을(수행·위촉받는 쪽)
- 단계: 협상 중 / 체결 직전 / 체결 후(분쟁 대비)
- 형식: HTML / DOCX / 둘 다 (기본: 둘 다)

검토 초점은 묻지 않고 전체를 본다.

## 2. 조항별 분석은 Claude가 직접 한다

`legal_research(task=document_review)`는 키워드 규칙 기반이라 일방 해지·무과실 배상·포괄 양도를 놓친다(2026-10-04 실측). 보조로만 쓴다.

반드시 보는 항목: 대금(금액·지급 시기·검수 조건·지연이자), 해지·해제(일방성·예고 기간·정산), 손해배상·위약금(상한·과실 요건), 지식재산·저작권 귀속, 비밀유지, 재위탁, 하자담보·수정 횟수, 분쟁 해결(관할 법원), 개인정보 처리, 자동 갱신.

## 3. 근거 조회 (korean-law MCP)

- 조문: `search_law` → `get_law_text(jo="제398조")`. 자주 쓰는 것: 민법 제387조(이행지체)·제397조(금전채무)·제398조(배상액 예정, 과다하면 감액)·제543조 이하(해지·해제)·제664조 이하(도급)·제680조 이하(위임), 약관법 제6조~제14조, 하도급법, 저작권법 제45조(양도), 개인정보보호법 제26조(위탁).
- 판례가 필요하면 `search_decisions(domain="precedent")`.
- 보고서의 모든 법 인용은 내보내기 전에 `legal_analysis(mode=verify_citations)`로 검증. 실패한 인용은 지우거나 "확인 필요"로 표시.

## 4. 산출물

1. **검토 보고서**: 한눈에 보는 결론(먼저 협상할 3가지) → 위험도 표(조항·문제·근거·제안) → "공식 근거 N건 / 확인 필요 N건" → 상대방에게 물을 질문 → 조항별 상세.
2. **수정 제안본**: 원본은 그대로 두고 별도 문서로. 조항마다 `원문 | 제안 | 이유`, 새 조항은 [신설 제안]으로 표시.

저장: `~/Desktop/cysjavis/법률_대응/<계약명>_검토보고서.html|docx`, `<계약명>_수정제안본.docx`. DOCX는 docx 스킬을 쓴다.

## 5. 멈춤선

금액이 크거나 이미 분쟁 중이면 보고서 끝에 "변호사 검토 권고"를 굵게 넣는다. 상대방에게 직접 보내는 일(메일·메시지)은 하지 않는다.

# korean-doc-corpus — 한국 공공문서 → 통일 마크다운 코퍼스

> 출처 아이디어: dbhyeong.github.io 관보/제도 파이프라인 정리(2026). 방법론만 이식했으며
> 그 프로젝트의 corpus 전용 사전값은 복사하지 않는다(과적합 방지 — 아래 주의 참조).

## 1) 언제 사용하나 (When)
- 여러 공공문서(PDF·HWP·HWPX·DOCX)를 **일괄로 AI-readable 마크다운**으로 만들 때.
- **스캔본 PDF**(이미지 PDF)라 OCR 후 **깨진 글자·표 손상**을 보정해야 할 때.
- 만든 마크다운을 **RAG/검색/비교**에 쓰려고 frontmatter 메타·인덱스가 필요할 때.
- **쓰지 말아야 할 때(위임)**: 파일 1개 단순 파싱=`read-hwp`(HWP/HWPX)·직접 pdfplumber(텍스트 PDF);
  HWP 내용 수정=`rhwp-edit`; HWPX 보고서 신규 작성=`hwpx-mouseco`; 데이터셋 찾기=`public-data-finder`.
  이 스킬은 "여러 포맷을 하나의 코퍼스로 수렴 + 스캔 OCR 보정 + 인덱싱"이 필요할 때만.

## 2) 순서 (Procedure)
1. **포맷 판별 → 라우팅** (포맷이 다르면 도구가 다르다. 출구는 하나의 마크다운):
   | 포맷 | 접근 | 도구 |
   |---|---|---|
   | HWP(구형 바이너리) | 레코드 파서 | **`read-hwp`(kordoc)** 호출 |
   | HWPX(개방형 XML/OWPML) | XML 파싱, 표 태그 직접 추출 | **`read-hwp`(kordoc)** 호출 |
   | DOCX(OOXML) | 압축해제 후 document.xml, `<w:tbl>` | python-docx |
   | PDF(텍스트형) | 텍스트+좌표 추출·재조립 | pdfplumber / PyMuPDF |
   | PDF(스캔형·이미지) | **OCR 필수** → 3단계 보정 | OCR(tesseract 등) + 아래 3) |
   - 판별 팁: PDF에서 `extract_text()` 결과 길이가 0/극소면 스캔형 → 페이지 이미지 추출 후 OCR.
2. **스캔 PDF면 OCR 보정**(3)을 적용. 나머지 포맷은 표를 마크다운 표로 보존.
3. **통일 출력**: 문서 1건 = 마크다운 1개. 상단 frontmatter 필수(4).
4. **(선택) 인덱싱**: 파일명 규약 + 정적 JSON(meta/dates/titles) 생성(5). DB·서버 불필요.
5. **원본 보존**: 원본 PDF/HWP는 **그대로** 두고, 파생 마크다운만 생성. frontmatter `source_raw_md`로 역추적.

## 3) 스캔 PDF OCR 깨짐 보정 방법론 (이 스킬의 핵심 · LLM 없이 결정론)
> 원칙: **추출보다 보정이 본체.** 승부는 사전·정규식·순서 설계에서 난다.
- **사전 기반 순차 치환(도메인별)**: 공통어휘 → 기관·금융 → 관계어 → 지명 → 법령·공직 → 잔여.
  문서 종류에 맞는 **자체 사전을 점진적으로** 쌓는다(관보·정관·고시마다 깨짐 패턴이 다름).
- **정규식 보정**: 반복 패턴을 일괄 수정. 예) 연도표기 `(\d{4})<깨진글자> → \1년` 하나로 수만 건 교정.
  표 셀·토큰·구문·"숫자+단위" 4계열을 우선 대상으로.
- **★단일 문자 치환은 반드시 맨 마지막**에, 그리고 **이웃 분포 검증**(그 글자가 등장하는 앞뒤
  문맥 1,000+ 샘플을 스캔해 안전할 때만 치환). 성급한 전역 단일치환이 "모친동산" 같은 **과보정 사고**를 낸다.
- **2-Pass**: 사전 1차 적용 → 정규식 → (검증된)단일치환 → 사전 2차 재적용.
- **수렴 판단**: "빈도 N 이상 잔존 깨짐 토큰 수"를 지표로. 줄어드는 폭이 미미해지면(diminishing returns) 중단.

## 4) 통일 frontmatter (RAG·역추적의 값어치)
```markdown
---
title: <문서 제목>
publisher: <발행기관>        # 광역+기초 결합해 세분화 권장
date: <YYYY-MM-DD>
source_raw_md: <원본 PDF/HWP 상대경로>   # ★원본 역추적 앵커
category: <Articles|Notice|Law|...>
status: ingested
---

# <제목>
<본문: 표는 마크다운 표로, 조문은 §앵커로>
```
- 파일명 규약(경로가 1차 색인): `readable/YYYY-MM-DD/NNN_기관_제목.md`
- 조문 단위 비교가 필요하면 **§조문 앵커**를 달아 원본과 대조 가능하게.

## 5) (선택) 정적 인덱스
- `meta.json`(기관 트리·월별 히트맵) · `dates/YYYY-MM-DD.json`(날짜별 목록) · `titles.json`(제목검색).
- 브라우저 `fetch`로 CORS 없이 접근 → DB/서버 없이 정적 사이트에서 검색 가능.

## 6) 주의할 점 (Pitfalls) — 넘어진 사람이 팻말을 세운다
- ❌ **원문 corpus 전용 사전값을 그대로 복사 금지**(옄→위 류). 그건 특정 데이터 과적합.
  가져올 것은 **방법**(사전+regex+이웃검증+과보정 가드)이지 매핑표가 아니다. 문서마다 새로 쌓는다.
- ❌ 단일 문자 전역 치환을 먼저 하지 말 것 → 과보정. **항상 맨 마지막 + 이웃분포 검증**.
- ❌ 기존 스킬 재구현 금지: HWP/HWPX는 반드시 `read-hwp`로 위임(중복·충돌 방지).
- ✅ **원본 불변**: 원본 PDF/HWP는 위변조 방지용 법적 원본. 파생 레이어만 생성.
- ✅ **외부 비공개 의존성 0** 지향: 누구든 같은 입력에서 같은 결과를 재현할 수 있게.

## 7) 확인하는 방법 (Verification)
- [ ] 각 마크다운에 frontmatter 4필드(title·publisher·date·source_raw_md) 존재.
- [ ] `source_raw_md`가 실제 원본 파일을 가리키는지 무작위 표본 대조.
- [ ] 표가 마크다운 표로 보존됐는지(셀 깨짐 없음) 표본 확인.
- [ ] "빈도 N 이상 잔존 깨짐 토큰 수"를 재계산해 보정 전후 감소 확인.
- [ ] 조문 인용이 있으면 §앵커로 원본과 대조(예: 조문 55개 중 표본 대조).
- [ ] HWP 경로가 `read-hwp` 산출과 동일 형식인지(중복 파서 아님) 확인.

# motion-tone-qa

출처: Ai-Con Lab 「120시간동안 오퍼스 5.5로 모션그래픽을 테스트해봤다」(J4PbF8_u6pY, 2026-10-08). 영상의 세 원칙을 기계로 옮긴 것.
1. "멋있게" 대신 톤 카드: 규칙 + 대표 사진 + 목표 숫자
2. 검수는 두 겹: 눈(24컷 한 장) + 숫자(기계). 만든 AI가 직접 채점하지 않는다
3. 실수는 규칙이 된다: FIX 항목은 과제지(프로젝트 지침·주문서)에 한 줄씩 추가

기존 자산과 나눈 일: `video-verify`는 비전 4관문만 하고 측정 스크립트는 없다. 이 스킬은 숫자만 맡는다.

## 쓰는 법
```bash
S=~/.claude/skills/motion-tone-qa/scripts/measure.py
python3 $S 참고1.mp4 참고2.mp4 --save-card 설교묵상          # 1) 톤 카드 만들기 (잘 된 내 영상 2~5편)
python3 $S 결과.mp4 --card 설교묵상 --sheet                  # 2) 결과 재기 + 24컷 PNG
python3 $S 결과.mp4 --card 설교묵상 --script 대본.txt --source 화면문구.txt   # 3) 숫자 대조
```
종료 코드 0=PASS, 1=FIX. 카드는 `cards/<이름>.json`(손으로 고쳐도 된다).

## 렌더와 자동 연결 (2026-10-09)
claude-motion-studio `render_hq.mjs`가 렌더 직후 measure.py를 부른다. 카드는 `--card 이름` > 작업폴더 `tone_card.txt` 순. 결과는 `tone_qa.txt`·`clip_hq_24컷.png`, 콘솔에 `QA 카드: PASS/FIX`. FIX여도 렌더는 성공으로 남는다. 끄기 `--no-qa`.

## 저장된 톤 카드 (2026-10-09)
| 카드 | 참고 영상(납품본 clip_hq) | 밝기 | 움직임 | 컷 | 정지 허용 |
|---|---|---|---|---|---|
| 설교묵상 | 시편23 예시 40초 · 고전15 본문카드 8초 | 20.1~31.0 | 0.20~0.36 | 끊지 않음 | 4.18초 |
| QT쇼츠 | QT쇼츠 2026-10-04 16초 (1편뿐) | 214.2 | 1.37 | 끊지 않음 | 1.73초 |
| 설교인트로 | 샘플 12 설교 시리즈 인트로 14초 (음량 보정 후, 1편뿐) | 28.1 | 1.15 | 끊지 않음 | 1.0초 |

- 카드는 `render_hq.mjs` 납품본(모션블러) 기준이다. 미리보기 `clip.mp4`는 블러가 없어 움직임이 1.4~4배 높게 나오니 납품본만 잰다.
- 판정은 참고 영상들의 최소~최대 범위에 허용 오차를 더한 구간이다. 참고 영상은 같은 렌더 경로로 맞춘다.
- 음원이 있는 참고 영상이 없어 LUFS 기준(-16~-12)은 아직 시작값이다.

## 재는 것
| 항목 | 방법(ffmpeg) | 판정 |
|---|---|---|
| 밝기 | signalstats YAVG 평균 | 목표 ±25% |
| 움직임 | signalstats YDIF 평균 | 목표 ±40% |
| 컷 간격 | scene>0.3 전환 수 → 길이/(컷+1) | 목표 ±30% (영상 기준: AI는 다시 돌리면 1.7배 급해진다) |
| 정지 | freezedetect 1초 이상 | 참고 영상 최대 정지보다 길면 FIX |
| 음량 | ebur128 통합 LUFS | 카드 범위(기본 -16~-12) |
| 숫자 대조 | 화면 문구의 숫자 − 대본의 숫자 | 하나라도 있으면 FIX (영상: AI가 '60개'를 지어냄) |

## 한계
- 부드러운 전환(모핑·연속 카메라)은 컷으로 안 잡힌다. 컷 간격은 '끊는 톤'에서만 의미가 크다.
- 숫자 대조에 HTML 전체를 넣으면 px·ms 숫자가 섞인다. 화면 문구만 뽑은 텍스트를 주는 편이 정확하다.
- 허용 오차는 영상의 30%만 출처가 있다. 나머지(25·40%)는 시작값이고, 실측하면서 고친다.

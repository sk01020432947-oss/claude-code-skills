# daily-radar-magazine

영상 시연의 3단계(정기 조사 → 매거진 웹 → 링크 공유)를 그대로 따른다. 새 인프라를 만들지 않고 이미 있는 것만 엮는다.

| 영상(Codex·Vercel) | 여기서 쓰는 것 |
|---|---|
| Codex 앱 예약 작업(매일 9시) | `mcp__scheduled-tasks__create_scheduled_task` (로컬) 또는 `/schedule` (클라우드 루틴) |
| 웹 검색·스크래퍼 | WebSearch, `naver-news-search`, `korean-law`(ordinance_radar), `last30days`, 도메인 MCP |
| 매거진 웹사이트 | `artifact-design` 규약의 HTML 1장 |
| Vercel 배포 링크 | Artifact 발행 — **처음 한 번만 새 URL, 이후 항상 같은 `url`로 갱신** |

## 1. 레이더 정의 (처음 한 번)

`~/Desktop/cysjavis/<주제>/<레이더이름>/레이더설정.md`에 적는다.

```yaml
이름: 지방의회 조례 레이더
시각: 매일 09:00 (Asia/Seoul)
대상: [순천시 조례 입법예고, 전라남도 조례, 행안부 지방재정 지침]
출처_우선순위: [공식(법제처·자치법규정보시스템·기관 누리집), 공영/전문매체, 기타]
창: 최근 7일   # 영상 교훈 — 하루 창은 '오늘 없음'만 뜬다
제외: [광고, 단순 재게시, 출처 없는 루머]
발행: { 정본: 매거진.html, 아티팩트_URL: (첫 발행 후 기록) }
```

## 2. 매 회차 실행 순서

1. 대상별 검색 → 후보 수집 (창 = 설정값).
2. **교차 확인**: 공식 출처 1개 이상 + 다른 출처 1개. 공식 확인이 없으면 `미확인` 칸으로만 보낸다. 날짜·수치는 출처 링크와 함께만 적는다.
3. 지난 회차와 비교해 `새로 나옴 / 변동 / 그대로`를 표시한다 (정본 폴더의 `기록/YYYY-MM-DD.json`).
4. 정본 `매거진.html` 갱신 — 맨 위 "오늘의 3줄", 대상별 카드, 미확인 칸, 출처 목록.
5. 기록된 아티팩트 URL로 재발행. URL이 없을 때만 새로 발행하고 즉시 설정 파일에 적는다.
6. 새 항목이 0건이면 발행하지 않고 "변동 없음" 한 줄만 남긴다.

## 3. 예약 등록

예약 등록은 지속 설정이므로 사용자에게 시각·대상을 한 번 확인받고 등록한다. 프롬프트 본문:

```
daily-radar-magazine 스킬로 <레이더설정.md 경로>를 실행해. 교차 확인 안 된 항목은 미확인 칸으로.
```

## 금지선 (영상에서 나온 경고)

- 결제·구매·예매 확정은 하지 않는다. 장바구니/결제창 직전에서 멈추고 사람에게 넘긴다.
- 로그인 비밀번호·카드 정보를 레이더에 넣지 않는다. 필요하면 AI 전용 계정을 따로 쓴다.
- 개인 민감 대화·교인 정보는 레이더 대상에서 뺀다.

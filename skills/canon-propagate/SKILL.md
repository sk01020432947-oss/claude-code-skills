# canon-propagate — 정본 한 번 고치면 사본까지 한 번에

근거: 2026-10-04 작업 학습집 §3④·승인 3번, 공유 기억 `propagate-canonical-to-all-copies`.
고전 15장 설교에서 "3~5절 개역개정으로 교체" 뒤에 설교문·프롬프터·도식, 종합본·hwpx·Obsidian, NotebookLM 소스, 인포그래픽·손그림·리포트를
12분 사이 6번 나눠 지시해야 했다. 이 스킬은 교체 전에 사본을 전부 찾고, 한 번에 바꾸고, 표로 보고한다.

## 1. 사본 대장 — `사본목록.json`

설교(또는 강의) 폴더마다 하나를 둔다: `~/Desktop/cysjavis/설교/<폴더>/사본목록.json`. 없으면 2단계 탐색 결과로 새로 만든다.

```json
{
  "정본": "고전15_1-11_받은복음_설교문.md",
  "갱신": "2026-10-04",
  "사본": [
    {"종류": "발표자료", "경로": "받은복음_발표.html"},
    {"종류": "hwpx", "경로": "받은복음_종합본.hwpx"},
    {"종류": "obsidian", "경로": "~/obsidian/<볼트>/<노트>.md"},
    {"종류": "notebooklm", "노트북": "<notebook_id>", "소스": "<source_id>", "원본파일": "받은복음_종합본.md"},
    {"종류": "아티팩트", "url": "https://claude.ai/artifact/…", "원본파일": "받은복음_발표.html"}
  ]
}
```

## 2. 착수 전 사본 탐색 (교체보다 먼저)

1. 대장이 있으면 읽는다. 대장에 없는 사본이 있을 수 있으니 아래 탐색도 함께 한다.
2. 바꿀 **옛 문구**로 찾는다. 한글 경로·NFD 문제 때문에 셸 글롭 대신 python3으로 정규화(NFC)해서 찾는다(CLAUDE.md 규칙 6).
   - 정본 폴더 전체: `.md .html .txt .json .svg` 본문 검색, `.pptx .docx .hwpx`는 압축 안 XML까지 검색.
   - Obsidian 볼트(`~/obsidian/`)에서 같은 문구·같은 정본 링크를 쓰는 노트.
   - NotebookLM: `nlm source list <notebook>`로 소스 목록, 필요하면 `nlm source content <source>`로 문구 확인.
   - 아티팩트: 대장·폴더 안 기록에 남은 URL.
3. 찾은 사본 목록을 사용자에게 먼저 보여 준다(한 번에 표 하나).

## 3. 교체

| 사본 종류 | 방법 |
|---|---|
| md·html·txt·svg | 옛 문구 → 새 문구 정확 치환. 치환 개수를 센다. |
| hwpx | kordoc `patch_document` 또는 hwpxskill. 서식 보존을 확인한다. |
| pptx·docx | python-pptx·python-docx로 텍스트 런 치환. 런이 쪼개져 못 바꾸면 "못 바꾼 것"에 넣는다. |
| PNG·PDF(인포그래픽·손그림) | 원본 HTML·소스를 고쳐 다시 렌더한다. 원본이 없으면 "못 바꾼 것". |
| Obsidian | 노트 본문 치환. frontmatter·링크는 건드리지 않는다. |

로컬 파일은 교체 전에 같은 폴더 `_교체전_<날짜>/`에 사본을 남긴다.

## 4. 덮어쓰기 전 확인 (NotebookLM·아티팩트)

다음 둘은 되돌리기 어렵거나 다른 사람이 보는 곳이므로, **로컬 교체가 끝난 뒤 한 번에 묶어 확인을 받고** 진행한다.

- **NotebookLM 소스**: 소스 내용은 고칠 수 없어 "새 소스 추가 → 옛 소스 삭제"가 된다. `nlm source delete`는 영구 삭제다.
  확인 문구에 노트북·소스 이름, 새로 올릴 파일, 삭제될 소스 ID를 적는다. 승인 전에는 새 소스 추가까지만 하고 삭제하지 않는다.
- **아티팩트**: 정본 HTML을 고친 뒤 **기록된 URL을 `url`로 넘겨** 재발행한다(새 URL 금지, CLAUDE.md 규칙 1). 확인 문구에 URL과 바뀌는 부분을 적는다.

## 5. 보고와 대장 갱신

보고는 표 하나로 끝낸다.

| 사본 | 종류 | 결과 | 치환 수 / 사유 |
|---|---|---|---|
| … | hwpx | 바꿈 | 3 |
| … | notebooklm | 승인 대기 | 새 소스 추가 완료, 옛 소스 삭제 대기 |
| … | png | 못 바꿈 | 원본 HTML 없음 |

- 이번에 찾은 사본을 `사본목록.json`에 반영하고 `갱신` 날짜를 바꾼다.
- 학습 효과 측정용으로 "이번 교체에서 사용자가 사본을 따로 다시 지시한 횟수(사본 누락 수)"를 한 줄 기록한다.

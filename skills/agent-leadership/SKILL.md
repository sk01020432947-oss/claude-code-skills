# agent-leadership — 에이전트 조직 경영 방법론

> 출처: 티타임즈TV 「이 사람이 조율, 실행, 리뷰, 판단 에이전트들과 일하는 법」(강정구 라이너 AI전략 총괄 / 진행 이중학 동국대 교수, 2026-08-12, 25분)
> 프레임·용어·사례는 원본 발언 기반. 카탈로그(50 롤·25 어드바이저 상세 목록)는 원본이 카테고리만 밝힌 부분을 **재구성**한 것이며 `references/casting-roster.md`에 그 경계를 표시해 두었다.

## 0. 이 스킬의 자리

| 질문 | 담당 |
|---|---|
| 이 조직은 AI를 어디까지 쓰고 있고, 다음에 뭘 해야 하나 | **이 스킬** |
| 에이전트/스킬 파일을 실제로 만들어 달라 | `harness` |
| 구현·검증을 자율 하네스로 오래 돌려 달라 | `harness-engineering` |
| 발표자료로 만들어 달라 | 덱 스킬 계열(`monoline-deck` 등) |

이 스킬은 **기술 산출물이 아니라 경영 판단**을 만든다. 코드가 아니라 진단표·역할설계·변화관리 계획이 산출물이다.

## 1. 라우팅

사용자 요청을 읽고 아래 모드 중 1~3개를 골라 실행한다. 애매하면 A(3축 진단)부터 시작한 뒤 병목이 가리키는 모드로 넘어간다.

| 모드 | 발동 신호 | 산출물 |
|---|---|---|
| **A. 3축 진단** | "우리 회사 AX 어디쯤", "뭘 먼저 해야 하나", 도입 기획 | 3축 현황표 + 병목 1개 지목 + 다음 90일 |
| **B. 레벨 진단** | "AI 잘 쓰는 게 뭔가", "레벨 진단", 개인/팀 역량 | L0~L5 판정 + 승급 조건 3개 |
| **C. 파이프라인 설계** | "에이전트로 내 업무 돌리고 싶다" | 7단계 워크플로 정의서 |
| **D. 캐스팅** | "이 일에 어떤 에이전트가 필요한가" | 팀 편성표(오케스트레이터+팀원+가드레일) |
| **E. Five Colors 리뷰** | 초안·보고서·기획서 검토 요청 | 5색 리뷰 리포트 + 수정 우선순위 |
| **F. 어드바이저 보드** | "결정하기 어렵다", 전략적 딜레마 | 소집된 3~7인 관점 + 판단 프레임(결정은 사람이) |
| **G. 인사 6단계** | "에이전트를 어떻게 관리하나", 자율성 범위 | 채용~보상 6단계 운영규칙 |
| **H. 변화관리** | "직원들이 안 쓴다", "저항감", 교육 설계 | 저항 지도 + X톤 설계안 |
| **I. 이해 병목 진단** | "리더가 병목", "결정이 늦다", "에이전트 결과 읽다 지친다", "같은 검토 반복" | 이해 흐름 지도(누가 무엇을 꼭 이해해야 하나) + 반복 검증→규칙 전환표 + 결정 브리프 양식 |
| **J. 온톨로지 설계** | "조직 지식 체계화", "교회 온톨로지", "AI가 우리를 모른다" | 개체·관계 목록 + 사실/관찰/의견/에피소드 기록 규약 + 프라이버시 가드 + 자체 벤치마크 10문항 |
| **K. 성장 사다리 진단** | "누구에게 맡길까", "리더 키우기", "E3~E7", "일꾼 성숙" | 5계단(완수→자기주도→책임→리더에게 가치→판 밖 영향) 판정 + 다음 계단 과제 3개 |

프레임 원문·정의는 `references/frameworks.md`, 실행 절차와 템플릿은 `references/playbooks.md`, 롤 카탈로그는 `references/casting-roster.md`에서 필요한 것만 읽는다. I·J·K 모드는 `references/understanding-bottleneck.md`를 읽는다.

## 2. 항상 지키는 6원칙

1. **리더가 먼저 쓴다.** AI는 리더가 승인하는 것이 아니라 주도하고 함께하는 것(DBS 사례). 리더가 안 써 본 도구는 조직에 퍼지지 않는다.
2. **바이브 코딩 함정을 깬다.** "어떤 모델 쓸까(1번)"와 "이 업무를 AI로 전환(5번)"만 묻는 상태는 도입이 아니라 실험이다. 업무 구조(왼쪽)·협업 구조(오른쪽)·가드레일과 성장경로(아래)를 같이 설계해야 AX다.
3. **용어를 산출물 수준으로 번역한다.** 에이전트·스킬·MCP·하네스·루프·컴파니 브레인은 전부 신조어다. "우리 회사에서 저건 구체적으로 뭐가 나오는 건가"로 바꿔 말하지 않으면 의사결정이 멈춘다.
4. **무게중심은 채용이다.** 사람은 해고가 어려워 평가가 핵심이지만, 에이전트는 안 돌면 지우고 다시 만든다. 리더십의 초점이 평가 → 채용(설계)으로 이동한다.
5. **최대 병목은 두려움이다.** 저항감은 기술 문제가 아니라 "두렵다고 말하면 도태되어 보인다"는 조직 문제다. 잘하는 사람일수록 보이는 게 많아 더 두려워한다.
6. **개인 증강이 조직 증폭의 전제다.** 개인이 AI를 잘 쓰지 못하면 증류할 암묵지 자체가 생기지 않는다. 개인=증강(도구 아닌 동반자), 조직=증폭(암묵지 자산화).

## 3. 산출물 형식

모든 모드의 답은 이 3단 구조를 유지한다. 길게 쓰지 말고 판단 가능하게 쓴다.

```
[진단]  지금 여기 있다 — 근거 2~3개
[병목]  막힌 것은 이것 하나 — 왜 이게 1순위인지
[다음]  이번 주 / 이번 분기 각각 한 걸음 — 담당·산출물·판정기준
```

- 숫자와 고유명사는 사용자가 준 것만 쓴다. 조직 정보가 없으면 **먼저 5개 이하로 묻는다**(업종/규모, 현재 쓰는 AI, 최근 실패 사례, 의사결정 구조, 6개월 목표).
- 원본 인터뷰에 없는 내용을 덧붙일 때는 "원본 프레임 밖의 제안"이라고 표시한다.
- 사용자가 목사·비영리·교회 맥락이면 조직 용어를 그 맥락으로 치환한다(임원→당회/운영위, 해커톤→사역 실험주간 등).

## 4. 빠른 실행 예시

**"우리 팀 AI 도입 어디서부터?"** → A로 3축 표를 채우고, 대부분 조직이 3번(HAT)에서 막히므로 그 근거를 확인한 뒤 H(변화관리)로 연결. 1·2번은 계획으로 풀리지만 3번은 철학·역사와 얽혀 있어 시간이 걸린다는 점을 명시한다.

**"내 업무를 에이전트로 돌리고 싶다"** → C로 7단계를 채운다. 이때 1단계(목표)와 7단계(판단)는 **절대 위임하지 않는 사람의 자리**임을 먼저 못 박고, 2~6단계만 설계한다.

**"보고서 초안 봐 달라"** → E. 블랙(집필)의 결과물을 레드(비판)·블루(옹호)·실버(전문성)·골드(돈 내는 사람) 순으로 통과시키고, 골드의 반응을 최우선 수정 근거로 삼는다.

# 모드별 실행 플레이북

각 모드는 **질문 → 채우기 → 판정 → 다음 한 걸음** 순으로 진행한다. 표는 그대로 복사해 쓰되, 빈칸을 억지로 채우지 말고 "모름"은 모름으로 남긴다 — 모름의 분포 자체가 진단이다.

---

## 모드 A — AX 3축 진단

### 먼저 묻기 (최대 5개)
업종·규모 / 지금 조직이 실제로 쓰는 AI 도구 / AI 도입 시도 중 실패한 것 / 의사결정이 내려지는 자리 / 6개월 뒤 원하는 상태.

### 채우기

| 축 | 지금 상태 | 근거(사실) | 담당 | 판정 |
|---|---|---|---|---|
| 1 프런티어 모델 | | 어떤 모델을 누가 결재했나 | | 미착수/실험/운영 |
| 2 컴퍼니 브레인 | | 스킬 라이브러리·MCP 연결·날리지 베이스 각각 존재하나 | | 미착수/부분/누적중 |
| 3 휴먼-에이전트 팀 | | 에이전트 사용이 인사·평가·업무분장에 반영됐나 | | 미착수/논의중/제도화 |

### 병목 판정 규칙
- 3축 중 **가장 낮은 축이 병목**이다. 대부분 3번에서 막힌다.
- 2번이 "부분"인데 **소통·보고 체계가 그대로**라면, 그건 구축이 아니라 일회성 프로젝트다 → 실질 병목은 2번.
- 1·5번(모델·업무전환)만 논의 중이라면 → **바이브 코딩 함정**. 병목은 "업무 구조를 아무도 문서화하지 않았다"일 확률이 높다.

### 다음 한 걸음 (병목별)
- **1번 병목** → 리더 1인이 자기 업무 하나를 프런티어 모델로 끝까지 끌어내 보고 그 한계를 기록.
- **2번 병목** → 이번 달 논의를 에이전트로 정리한 **내부 뉴스레터 1호** 발행. 보고서 1건을 노션 한 줄 + 30분 캐치업으로 대체.
- **3번 병목** → 모드 G(인사 6단계)와 모드 H(변화관리)로 이동.

## 모드 B — AI 활용 레벨 진단

### 판정 질문 (예/아니오)
1. 저장해 두고 반복해 쓰는 프롬프트가 5개 이상 있다 → L2
2. 사람이 손대지 않아도 조건이 맞으면 돌아가는 워크플로가 있다 → L3
3. 역할·평가기준·컨텍스트·도구·순서·가드레일을 문서로 정의한 에이전트가 있다 → L4
4. 시작 조건과 정지 조건, 인간 개입 지점을 정의한 자동 순환이 있다 → L5

### 산출

```
현재 레벨: L_
근거: (해당 레벨의 증거 2개)
다음 레벨 승급 조건 3개:
  1. (설계 대상이 무엇으로 바뀌어야 하는가)
  2. (누가 언제까지)
  3. (승급을 확인할 판정 신호)
```

> 승급 처방은 "도구를 더 써라"가 아니라 **설계 대상의 이동**으로 쓴다: 답 → 프롬프트 → 워크플로 → 팀·가드레일 → 순환 조건.

## 모드 C — 7단계 파이프라인 설계

사용자의 반복 업무 1건을 골라 아래를 채운다. **1·7단계는 사람의 자리로 고정**하고 시작한다.

| 단계 | 채울 것 | 실패 신호 |
|---|---|---|
| 1 목표 | 한 문장 목표 + 완료 판정 기준 | 목표가 "잘 만들기"면 아래 전부 무의미 |
| 2 캐스팅 | 산출물 형식 + 필요한 롤 3~7개 | 롤이 10개 넘으면 목표가 안 쪼개진 것 |
| 3 실행 | 각 롤의 입력·출력·순서 | 산출물 형식이 없으면 재작업 발생 |
| 4 리뷰 | Five Colors 중 최소 레드·골드 | 리뷰어가 집필자와 같은 컨텍스트면 무효 |
| 5 윤문 | 문체 기준(누가 읽는가) | AI 문체 잔존 = 신뢰도 하락 |
| 6 검증 | 출처 검증 범위와 깊이 | "출처 있음"과 "출처 확인함"은 다르다 |
| 7 판단 | 결정 항목 + 유보 항목 | 판단까지 AI가 하면 책임이 사라진다 |

### 배치 요령
- 상황별 프롬프트 구조를 미리 짜서 **클로드/챗GPT 프로젝트에 붙여 두면** 바로 돌아간다.
- 자주 하는 업무 상황을 세어 본다. 30~40종으로 수렴하면 정상이다.
- 하네스는 **느슨하게 먼저** 준다. 모델이 구조를 잘 짜면 그대로 두고, 실패하는 지점에만 가드레일을 조인다.

## 모드 D — 캐스팅

1. 목표를 받는다 → 2. 산출물 형식을 먼저 정한다(보고서/장표/표/의사결정문) → 3. `casting-roster.md`에서 롤을 고른다 → 4. 오케스트레이터 1인을 세우고 순서를 짠다 → 5. 가드레일을 명시한다.

```
[목표]
[산출물 형식]
[오케스트레이터] 역할·판단 권한·에스컬레이션 조건
[팀원] 롤 / 입력 / 출력 / 순서
[가드레일] 하지 말 것 · 반드시 확인할 것 · 사람에게 물을 것
[정지 조건] 언제 멈추고 사람을 부르는가
```

## 모드 E — Five Colors 리뷰

입력 문서를 받아 5색 순서로 통과시킨다. 각 색은 **다른 관점을 강제**하며, 앞 색의 결론을 존중하지 않는다.

```
■ BLACK  요지 한 문장 / 구조 요약
■ RED    치명적 반론 3개 — 각각 "이게 사실이면 이 문서는 무너진다" 형식
■ BLUE   가장 강한 논거 3개 — 왜 이 안이 살아남는가
■ SILVER 사실·용어·방법론 오류 목록 (위치 + 정정)
■ GOLD   승인/구매 판단 + "그래서 뭘 하면 되나"에 답이 있는가
────────
수정 우선순위: GOLD → SILVER → RED (BLUE는 살릴 것 표시)
```

## 모드 F — 어드바이저 판단 보드

1. 결정할 질문을 **하나의 선택지 대립**으로 좁힌다(A냐 B냐, 하느냐 마느냐).
2. `casting-roster.md`에서 3~7인을 소집한다. **반대 관점 1인 필수.**
3. 각자 한 문단. 서로 충돌하는 지점을 표로 정리.
4. **결론을 합성하지 않는다.** 대신 "이 결정을 가르는 사실 질문 2~3개"를 제시하고 사용자에게 넘긴다.

```
[질문] A vs B
[소집] 이순신형 / 사전부검 / 자본배분가 / 반대매매자
[각 관점] 한 문단씩
[충돌 지점] 무엇에 대해 의견이 갈리는가
[판단을 가르는 사실 질문] 1. 2. 3.
[사람이 결정할 것] ...
```

## 모드 G — 인사 6단계로 에이전트 운영

| 단계 | 사람 조직 | 에이전트 조직 | 이번에 정할 것 |
|---|---|---|---|
| 채용 | 어렵고 되돌리기 힘듦 | **핵심** — 안 돌면 지우고 새로 | 어떤 롤을 만들 것인가 |
| 교육 | 온보딩·연수 | 컨텍스트·예시·레퍼런스 주입 | 무엇을 읽혀야 하는가 |
| 배치 | 조직 개편 | 워크플로 상 위치 | 앞뒤 단계는 누구인가 |
| 평가 | 리더가 할 수 있는 거의 유일한 것 | 평가 기준 = 하네스의 2번 요소 | "잘한다"의 정의 |
| **승진** | 직급 상승 | **자율성 부여 범위** | 어디까지 사람 확인 없이 실행하는가 |
| 보상 | 금전·인정 | 토큰·컨텍스트·도구 접근권 | 어떤 자원을 더 줄 것인가 |

> 승진(자율성)은 철저히 **리더의 의사결정 영역**이다. 이 결정을 안 하면 에이전트는 조직에 퍼지지 않는다.

## 모드 H — 변화관리 · X톤

### 저항 지도 만들기
| 대상 | 겉으로 말하는 이유 | 실제 두려움(추정) | 확인 방법 | 처방 |
|---|---|---|---|---|
| | "시간이 없다" | 못한다는 게 드러날까 봐 | 익명 서베이 | 실패 허용 선언 |
| | "보안 때문에" | 통제권 상실 | 1:1 | 가드레일 공개 |
| | "우리 일은 다르다" | 대체 위협 | 업무 관찰 | 역할 재정의 |

원칙: **두려움은 조직에서 말하기 어렵다.** "두렵다"고 말하면 도태되어 보이기 때문. 그래서 직접 묻지 말고 익명·간접으로 수집한다. 그리고 **잘하는 사람일수록 더 두려워한다**는 점을 전제로 설계한다.

### X톤 설계 템플릿
```
[대상] 특정 직급·연차로 묶는다 (임원, 팀장, 15년차 이상 등)
[기간] 반나절~1일
[과제] 각자의 실제 업무 1건을 에이전트로 전환
[발표] 결과가 아니라 시행착오를 말하게 한다
[포상] 후하게 — 성공이 아니라 시도에 준다
[중계] 전사 라이브 ← 이게 핵심. 리더가 헤매는 모습까지 보여준다
[부작용 관리] 스트레스·시간 압박 인정, 순위 매기지 않기
```

근거: 리더가 두려움 없이 재미있게 쓰고 성과를 만드는 걸 보여주는 것만큼 좋은 변화관리는 없다. MS Work Trend Index(2026) 프론티어 펌의 1번 특징도 "리더가 공개적으로 활용하고 공유하라"이다.

### 효율화 이후의 물꼬
효율화로 확보한 시간을 **어디에 쓸지 미리 정해 주지 않으면** 저항은 사라지지 않는다. "내 일을 효율화한 만큼 새로운 일을 할 수 있다"는 역할·시간의 재배치가 세트로 가야 한다.

# Design DNA — 레퍼런스 역설계 → 재사용 스킬 코드화

핵심 원칙: **묘사하지 말고 측정하라(measure, don't describe).** "따뜻한 느낌"은 규칙이 아니다.
"배경 #F2E9DC, 제목/본문 크기비 1:0.618, 여백 = 캔버스 짧은 변의 8%"가 규칙이다.

## 입력

1. 레퍼런스: 이미지 파일 경로, 스크린샷, 또는 영상이면 /watch로 추출한 프레임
2. 목표 포맷: 포스터 / 웹 그래픽 / 슬라이드 / 모션 그래픽 / HTML 이메일 등
3. 저장할 스킬 이름(슬러그) — 없으면 제안 후 확인

레퍼런스 이미지는 반드시 Read로 직접 본다. 보지 않고 진행 금지.

## 6단계 루프

### 1. 측정 (묘사 금지)
레퍼런스를 다음 렌즈로 전부 수치화해 기록한다:
- **비율**: 캔버스 비율, 요소 간 크기비(황금비 1.618, 1:2, 1:3…), 정렬 그리드
- **색**: 주요 색 hex + 면적 배분(60-30-10 대비 실측치)
- **타이포**: 서체 계열(세리프/산스/모노), 크기 단계, 행간, 자간, 대소문자 처리, 줄 수
- **여백·간격**: 마진/패딩을 캔버스 대비 %로, 간격 스케일(4/8/16…)
- **형태**: 모서리 반경, 선 굵기, 그림자(오프셋/블러/색), 곡선 스타일
- **레이아웃 이름 붙이기**: "상단 풀블리드 히어로 + 하단 3열 크레딧" 식으로 명명
- **특이수(weird moves)**: 이 디자인만의 이상한 선택 1~3개 — 이게 정체성이다
- **거부 목록(refusals)**: 이 디자인이 의도적으로 안 하는 것 (그라디언트 없음, 아이콘 없음 등)

### 2. 논쟁
측정치를 놓고 스스로 반박한다: "이 규칙이 빠져도 같은 디자인으로 보이는가?"
- 빠지면 무너지는 것 → **핵심 규칙(LOAD-BEARING)**
- 빠져도 티 안 나는 것 → 부차 규칙(OPTIONAL)
핵심 규칙은 보통 5~9개다. 20개가 넘으면 논쟁이 부족한 것이다.

### 3. 규칙 파일 작성
작업 폴더에 `DNA.md` 작성: 핵심 규칙(수치 포함) → 부차 규칙 → 거부 목록 → 특이수.

### 4. 불량 복제 테스트 작성
`DNA.md`에 "나쁜 복제본이라면 실패할 검증 항목" 체크리스트를 추가한다.
예: "제목 행간이 장식 요소 높이를 초과하면 FAIL", "3색 초과 사용 시 FAIL".

### 5. 재현 → 대조 → 보강
레퍼런스를 **보지 않고 DNA.md만으로** 결과물을 1개 재현한다(HTML/SVG 권장).
재현본과 레퍼런스를 나란히 대조한다. **틀린 부분 = 잊어버린 규칙**이다.
누락 규칙을 DNA.md에 추가하고 재현을 반복한다. 2회 연속 대조 통과하면 종료.

### 6. 스킬 패키징
`~/.claude/skills/<슬러그>/SKILL.md`를 생성한다:
- frontmatter description: 어떤 스타일이며 언제 발동하는지(한국어, 트리거 문구 포함)
- 본문: DNA.md 전문(규칙+테스트) + 생성 절차
- **인테이크 질문 명시**: 스킬 발동 시 사용자에게 물어야 할 빈칸(주제/전경/배경/카피 등)을
  스킬 본문에 박아, 매번 필요한 재료를 먼저 수집하게 한다.
완료 후 사용자에게 `/<슬러그>`로 재사용 가능함을 알린다.

## 이미지 생성이 필요한 경우

래스터 이미지·일러스트가 필요한 패널은 media-gen-image 스킬로 라우팅한다(이 PC의 기본 이미지 파이프라인).
HTML/SVG로 표현 가능한 것은 코드로 직접 만든다 — 재현성이 더 높다.

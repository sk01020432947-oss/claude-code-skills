# Knowledge Manager 연결 감사 스킬

> Vault 전체의 노트 연결 상태 진단 및 개선 제안

## ⚠️ 실행 방법 — 이 절이 아래 본문 전체보다 우선한다

**Phase 1~3(스캔·그래프 구축·문제 식별)은 직접 하지 말고 스크립트를 돌린다.**
7,000개 볼트를 Glob/Grep/Read로 훑으면 수천 번의 도구 호출이 들고 2분을 넘긴다.
같은 계산이 스크립트로는 3~7초다. 아래 본문의 Phase 1~3 절차와
`Obsidian.com` CLI 명령은 **읽지 말고 무시한다** — 이 PC에 CLI는 설치돼 있지 않다.

```bash
python "$HOME/.claude/skills/km-link-audit/scripts/vault_graph.py" \
  --vault "/Users/kbg1023/obsidian/Obsidian 2025" --top 25
```

| 상황 | 붙일 인자 |
|------|----------|
| 특정 폴더만 보고 | `--folder "002. Folder/Sermon"` (색인은 늘 볼트 전체 — 폴더 밖 링크도 정상 해석) |
| 큐레이션 상태만 보기 | `--no-raw` (미분류 원자료 `001. inbox`·`inbox`·`Clippings` 제외) |
| 한 노트의 이웃·연결 후보 | `--note "노트제목"` |
| 구조화 출력이 필요할 때 | `--json` |
| 스크립트가 의심스러울 때 | `--selftest` (의존성 없음, 즉시) |

스크립트는 표준 라이브러리만 쓴다. 설치할 것 없다.
**Phase 4(해석·우선순위)와 Phase 5(리포트)가 실제로 할 일이다** — 숫자는 스크립트가 주고,
그 숫자가 무엇을 뜻하는지 판단하는 것이 이 스킬의 몫이다.

### 이 볼트의 기준선 (2026-08-06 실측)

| 범위 | 노트 | 해석된 링크 | 고아 | 깨진 링크 | 개념링크 |
|------|-----|-----------|------|----------|---------|
| 전체 | 7,028 | 2,732 | 5,106 (72.7%) | 8,969 | 2,337 |
| `--no-raw` | 1,044 | 36 | 1,006 (96.4%) | 1,761 | 357 |

숫자가 이 근처면 정상이다. 크게 벗어나면 인자나 볼트 경로를 먼저 의심한다.

---

## 스킬 개요

1. 스크립트로 그래프 계산 (Phase 1~3을 대체)
2. 결과 해석 — 무엇이 진짜 문제이고 무엇이 볼트의 성격인지 가른다
3. 우선순위 분류 (Phase 4)
4. 진단 리포트 작성 (Phase 5)

---

## 해석 규칙 — 숫자를 그대로 옮기지 말 것

이 볼트에는 성격이 다른 두 영역이 섞여 있다. 구별하지 않으면 리포트가 거짓말을 한다.

- **미분류 원자료** (`001. inbox` 2,929 · `inbox` 1,796 · `Clippings` 1,228 = 전체의 85%)
  웹 클리핑과 미처리 자료다. 링크가 없는 게 정상이므로 **고아로 세는 것은 의미가 없다.**
  큐레이션 건강도를 물었다면 `--no-raw`로 돌리고, 그 사실을 리포트에 밝힌다.
- **깨진 링크 vs 미해결 개념링크** — 스크립트가 갈라 준다.
  여러 노트가 같은 대상을 가리키면(기본 3개 이상) 개념 허브를 미리 걸어둔 것이라
  **고칠 대상이 아니라 만들 대상**이다. 한두 노트만 가리키는 것이 오타이거나 옮겨진 파일이다.
  ★ 표시된 "깨진 링크"만 수정 대상으로 보고한다.
- **평균 링크 0.39개/노트**가 이 볼트의 현실이다. 원본 문서의 "권장 3~5개"를 기준으로
  판정하면 전부 낙제가 나온다. 개선은 절대 수치가 아니라 **직전 감사 대비**로 말한다.

## Phase 1~3 · 스크립트가 대신한다

위 [실행 방법]의 명령 한 줄이 스캔·그래프 구축·문제 식별을 모두 끝낸다.
아래는 스크립트가 쓰는 판정 기준이다. 결과를 해석할 때 참고하되, 절차를 손으로 반복하지 말 것.

| 항목 | 판정 기준 |
|------|----------|
| 링크 추출 | `[[대상]]` `[[대상｜별칭]]` `[[대상#섹션]]` `[[폴더/대상]]`. 코드 블록·인라인 코드 안은 제외하고, 색상코드(`[[e4e4e7]]`)처럼 링크가 아닌 것은 버린다 — 웹 클리핑이 CSS를 긁어와 만든 잡음이 이 볼트에 1,100건 있다 |
| 링크 해석 | 경로 지정 링크가 우선, 없으면 파일명 일치. 동명이 여럿이면 경로가 짧은 쪽 |
| 고아 | 나가는 링크 0 **그리고** 들어오는 링크 0 |
| 데드엔드 | 들어오는 링크는 있고 나가는 링크가 0 |
| 깨진 링크 ★ | 해석 실패 + 가리키는 노트가 2개 이하 → 오타이거나 옮겨진 파일 |
| 미해결 개념링크 | 해석 실패 + 가리키는 노트가 3개 이상 → 의도적. `--concept-threshold`로 조정 |
| 단방향 | A→B는 있는데 B→A가 없음 |
| 연결 부족 | 같은 폴더 평균 연결 수의 50% 미만 (폴더 평균이 2 이상일 때만 판정) |
| 허브 | 총 연결 10개 초과 |
| MOC 부재 | 같은 태그 노트 5개 이상인데 이름에 그 태그를 담은 MOC가 없음 |
| 제외 폴더 | `.obsidian` `.trash` `008. 첨부자료` `009. 설정` `100. Themes` `999-Attachments` `attachments` `Excalidraw` |

## Phase 4: 개선 제안 생성

### 4.1 우선순위 분류

```
🔴 High Priority (즉시 조치):
- 깨진 링크 (데이터 무결성 문제)
- 완전 고아 노트 5개 이상

🟡 Medium Priority (권장):
- 단방향 링크 → 양방향 전환
- 연결 부족 노트 강화

🟢 Low Priority (선택):
- 허브 노트(MOC) 생성
- 추가 연결 제안
```

### 4.2 자동 수정 옵션

**사용자 확인 후 자동 수정 가능:**
- 양방향 링크 추가
- 고아 노트에 관련 링크 추가
- auto_backlink_vault 도구 활용

**수동 수정 필요:**
- 깨진 링크 (파일 생성 또는 링크 수정)
- MOC 생성 (콘텐츠 작성 필요)
- 노트 병합/정리

### 4.3 고아 노트를 실제로 잇는 법

일괄 자동 백링크 도구(`auto_backlink_vault`)는 이 환경에 없다. 대신:

```bash
# 고아 하나하나의 연결 후보를 스크립트가 점수와 근거까지 뽑아 준다
python "$HOME/.claude/skills/km-link-audit/scripts/vault_graph.py" \
  --vault "/Users/kbg1023/obsidian/Obsidian 2025" --note "고아노트제목"
```

후보를 받으면 **본문을 읽고 판단한 뒤** `km-link-strengthening` 스킬로 링크를 넣는다.
점수는 후보를 좁히는 용도이지 근거가 아니다 — 점수만 보고 링크를 걸면
같은 폴더의 무관한 노트가 엮인다.

한 번에 여러 고아를 처리할 때도 **5개 이하씩** 끊는다. 링크 삽입은 되돌리기 번거롭다.

## Phase 5: 리포트 생성

### 5.1 리포트 저장 위치

**이 볼트에 `Changelog/` 폴더는 없다. 저장 위치를 사용자에게 묻는다.**
지정이 없으면 저장하지 말고 화면으로만 보고한다 — 볼트에 파일을 임의로 만들지 않는다.
파일명은 `Vault-Link-Audit-{YYYY-MM-DD}.md`.

### 5.2 리포트 템플릿

```markdown
---
tags: [audit, vault-health, report]
created: {YYYY-MM-DD HH:mm}
type: audit-report
---

# Vault 연결 감사 리포트

## 감사 정보
- 실행 일시: YYYY-MM-DD HH:mm
- 분석 범위: 전체 vault
- 총 분석 노트: N개

---

| 지표 | 값 | 직전 대비 |
|------|-----|----------|
| 분석 범위 | 전체 / `--no-raw` 중 어느 쪽인지 반드시 명시 | - |
| 총 노트 수 | N | - |
| 해석된 링크 | N | - |
| 평균 링크/노트 | N | ← 절대 기준 대신 직전 감사와 비교 |

| 깨진 링크 ★ | N | 이것만 "수정 대상" |
| 미해결 개념링크 | N | 수정 대상 아님 — 만들 후보 |
| 단방향 링크 | N | |
| 허브 노트 | N | |

> 원본에 있던 "권장 3~5개" 기준과 100점 만점 건강도 점수는 쓰지 않는다.
> 이 볼트 평균이 0.39개라 어떤 폴더를 재도 낙제가 나오고, 그 점수는 아무것도 알려주지 않는다.
> 개선은 **직전 감사 대비 증감**으로만 말한다. 첫 감사라면 기준선을 세웠다고만 적는다.
```

## 설정 옵션

전부 스크립트 인자다. 별도 설정 파일은 없다.

| 인자 | 기본값 | 설명 |
|------|--------|------|
| `--vault` | (필수) | 볼트 루트. 이 PC는 `/Users/kbg1023/obsidian/Obsidian 2025` |
| `--folder` | 전체 | 보고 범위. 색인은 항상 볼트 전체 |
| `--no-raw` | 꺼짐 | `001. inbox`·`inbox`·`Clippings` 제외 |
| `--exclude` | 첨부·설정·테마 폴더 | 제외 폴더 목록을 통째로 대체 |
| `--concept-threshold` | 3 | 이 수 이상이 가리키면 의도적 개념링크로 분류 |
| `--top` | 20 | 목록 출력 개수 |
| `--json` | 꺼짐 | 구조화 출력 |

리포트 저장 여부와 위치는 인자가 아니라 **사용자에게 묻는다.**

## 사용 예시

### 전체 감사

```
사용자: "vault 연결 감사해줘"

→ 전체 Phase 1-5 실행
→ 리포트 생성 및 저장
→ 자동 수정 옵션 제안
```

### 부분 감사

```
사용자: "고아 노트만 찾아줘"

→ Phase 1-3 중 고아 노트만 검사
→ 간략 결과 보고 (리포트 미저장)
```

### 특정 폴더 감사

```
사용자: "Zettelkasten 폴더만 연결 감사해줘"

→ 해당 폴더만 대상으로 감사
→ 폴더별 상세 통계 제공
```

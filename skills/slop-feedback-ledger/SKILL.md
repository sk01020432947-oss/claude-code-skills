# slop-feedback-ledger

출처: [공여사들 「클로드 코드로 감도높은 영상 만드는 법(실제 제작과정 공개)」](https://www.youtube.com/watch?v=FqERJgZSLUo) (29:31, 2026-10-02). 달피디가 푸티지 35개에 단 피드백 목록을 보여 준다.

이 스킬은 **만든 것을 판정하고 피드백을 남기는 일**만 맡는다. 만들기는 `web-motion-stack`·`claude-motion-studio`, 렌더 영상의 프레임 검수는 `video-verify`.

## 1. 판정: 슬롭 12개
`references/principles.md`의 S01~S12로 화면마다 본다. 걸린 것만 피드백한다.

| ID | 한 줄 | 영상 |
|---|---|---|
| S01 | 글은 그림으로. 텍스트는 꼭 필요할 때만 (자막이 이미 있다) | 05:37, 10:29 |
| S02 | 같은 단어 반복 대신 아이콘 하나 | 06:10 |
| S03 | 배지·라벨·장표 번호 붙이지 않기 | 12:40 |
| S04 | 왼쪽 위 목차 + 가운데 큰 글 + 아래 번호, 이 흔한 배치 금지 | 10:11 |
| S05 | 시선이 갈 곳은 하나. 나머지는 들러리 | 15:43 |
| S06 | 같은 역할의 상자는 크기를 맞춘다 | 11:42 |
| S07 | 실제 서비스 UI는 공개된 클론을 가져다 쓴다 | 04:18, 13:12 |
| S08 | 로고·아이콘은 SVG로, 이미 받아 둔 폴더에서 먼저 | 11:00, 12:13 |
| S09 | 자막 없이 봐도 의도가 보여야 한다 | 17:50 |
| S10 | 깜빡임(flicker)·끊김 없음 | 16:33 |
| S11 | 현실감 디테일 (링크면 OG 미리보기 카드) | 16:33 |
| S12 | 화면 대비 요소가 너무 작으면 키운다 | 17:21 |

색은 최소한 고정한다: 쓸 색과 쓰지 말 색을 적어 두면 일관성은 대부분 지켜진다 (09:35). 브랜드 가이드가 촘촘할수록 AI가 벗어날 틈이 줄어든다.

## 2. 피드백 한 줄 형식
```
NN · 대상 · 지시 · 이유(원칙ID)
03 · 2번 푸티지 '신청' 반복 · 입력폼 아이콘 하나로 · 같은 글 반복은 읽히지 않는다(S02)
```
- 이유를 꼭 붙인다. 앞에서 이유를 준 원칙은 뒤 항목에 짧게 "S05 위반"만 적어도 적용된다 (20:02, 21:24).
- 이유 없이 "초록→빨강"만 주면 그 한 건만 고친다.
- 병렬로 많이 맡기면 몇 개를 대충 한다. 그 항목에 "이건 대충 했다, 제대로"라고 한 줄 다시 준다 (17:21).
- 2차·3차 피드백까지만. 4차까지 갈 것 같으면 그 푸티지는 버린다 (06:27).

## 3. 원칙장부
작업 폴더에 `원칙장부.md`를 둔다. 피드백 회차가 끝날 때마다:
1. 이번에 처음 나온 이유를 원칙으로 일반화해 `P01…` 번호로 추가한다 (S 목록에 없는 프로젝트 고유 원칙).
2. 같은 원칙이 두 번 나왔으면 다음 생성 요청 맨 앞에 넣는다.
3. 새 세션은 만들기 전에 장부를 먼저 읽는다.

형식은 `references/ledger-template.md`.

## 4. 템플릿 등록 (이름 붙이기)
피드백이 끝나 승인된 화면은 다시 만들지 않는다 (07:30).
- 컴포넌트로 떼어 `templates/<이름>/`에 두고, **나만 쓰는 이름**을 붙인다 (예 `KBG-CHAT`). 이름을 부르면 AI가 새 스크립트를 짜지 않고 그 파일을 찾아 쓴다 (15:19).
- 등록부: 원칙장부 맨 아래 `## 템플릿` 표 (이름 · 경로 · 바꿀 칸 · 승인일).
- 예시: `samples/messenger-mockup/` — 메신저 대화 목업(링크 OG 카드 포함). 맨 위 `CONFIG.title`·`CONFIG.messages`만 바꾸면 된다 (영상 00:00, 650줄 → 50줄). 실제 메신저 로고는 넣지 않는다.
- 렌더: `node ~/.claude/skills/claude-motion-studio/scripts/render_hq.mjs <폴더> --scale 1 --fps 30` → `clip_hq.mp4` (1920×1080, `__seek` 규약). 미리보기 `?render&t=6`.

## 5. 모델 계층 (25:11)
1. 처음 만드는 화면·가능성 확인은 비싼 모델로.
2. 승인되면 4절대로 템플릿화 → 소재만 바꾸는 반복 작업은 Sonnet·Haiku로.
3. 소재까지 정해진 반복(주간 게시판 등)은 LLM 없이 스크립트만으로.
판단 질문: "이 품질을 싼 모델로도 다시 낼 수 있는가?" 못 내면 아직 내 실력이 아니라 모델 실력이다.

## 지킬 것
- 판정은 화면을 실제로 보고 한다(스크린샷·콘택트시트). 코드만 읽고 판정하지 않는다.
- 통계 수치를 화면에 넣을 때는 출처 있는 값만, 없으면 "예시" 표기.
- 피드백 원문(욕설 포함)은 장부에 옮기지 않는다. 이유만 남긴다.

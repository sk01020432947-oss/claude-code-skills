# final-report-lint — 최종보고 린트

근거: 비공식 공개본 「Claude Mythos 5.1 System Prompt」(github.com/sk010-****-****-oss/Claude-Mythos-5.1-System-Prompt)의 Claude Code 편 'Delivering work'·'Writing for the user' 절. 원문 출처·진위는 확인되지 않았다. 규칙 자체가 쓸모 있어 채택한다.

## 절차

1. 보고문을 파일로 두거나 표준입력으로 넘겨 린트한다: `python3 ~/.claude/skills/final-report-lint/scripts/lint.py <파일>`
2. 걸린 항목을 아래 표대로 고친다. 끝질문·미완약속은 문장을 고치기 전에 그 일을 지금 할 수 있는지 먼저 본다. 할 수 있으면 하고 보고에 결과를 적는다.
3. 다시 린트해 0건이면 끝낸다. 긴문장·괄호는 판단으로 남겨도 된다.

**종료 조건:** 끝질문·미완약속·서두가 0건이면 끝낸다. 나머지는 고침·보류로 한 줄씩 보고한다.

## 고쳐쓰기 표

| 항목 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 서두 | 네, 요청하신 내용을 살펴보겠습니다. | 설교 개요 3안을 만들었다. 2안을 추천한다. |
| 끝질문 | 원하시면 PPT로도 만들어 드릴까요? | (PPT가 요청 범위면 만들고 링크를 단다. 아니면 지운다.) |
| 미완약속 | 다음에 각주를 보완하겠습니다. | 각주 4개는 출처를 찾지 못해 비워 두었다. |
| 머리글 | 300자 보고에 `## 요약` `## 결과` | 머리글 없이 두 문단 |
| 줄표 | 끝났다 — 다만 남은 게 있다 | 끝났다. 남은 일이 하나 있다. |
| 수식어 | 솔직히 이 방법이 낫습니다. | 이 방법이 낫다. 이유는 둘이다. |

## 기억할 원칙 (린트로 못 잡는 것)

- 결론부터. 확인 못 한 것이 있으면 그것을 먼저 쓴다.
- 요청 범위가 산출물이다. 몰래 줄이거나 넓히지 않는다. 막힌 부분은 나머지를 다 끝낸 뒤 무엇을 왜 뺐는지 적는다.
- 숫자는 문장 대신 짧은 표나 한 줄에 둔다. 읽는 사람의 행동을 바꾸는 숫자만 쓴다.
- 세션 중에 지어낸 이름(작업명·임시 라벨)으로 부르지 않는다.
- 내용이 끝나면 멈춘다. 했던 일을 다시 요약하지 않는다.

`--selftest`로 린트를 점검한다. 휴리스틱이라 오탐이 있다.

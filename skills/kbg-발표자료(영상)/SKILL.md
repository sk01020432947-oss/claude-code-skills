# kbg-발표자료(영상) — 대본 하나로 만드는 발표 영상

출처: 바이브랩스, 「녹음/녹화/편집/모션 그래픽까지 클로드 코드에게 완전히 맡겨봤습니다」(2026-10-17, 11:13, 720p). 프레임 픽셀 실측값과 영상 설명·자막에서 뽑았다.
[template.html](template.html)이 정본 틀이다. 8장 예시(사진 무대·노드 타임라인·터미널·비교 카드·큰 숫자·프롬프트·붓글씨·마무리)가 들어 있으니 **구조와 클래스는 그대로 두고 내용만 바꾼다.**
원본 프레임은 [references/](references/)에 있다(프레임_01~07 = 영상 전체 60컷, 모션_* = 전환·타이핑·순차 등장 4fps 연속컷). 스타일이 애매하면 먼저 이걸 본다.

형제 스킬 `kbg-발표자료(1)`(코드팩토리 스타일: 블루 단일 강조·하단 자막·제목 없음)과는 다른 스타일이다. 섞지 않는다.

## 0. 시작 전 (전역 규칙)

- 발표자료이므로 **작업 시작 전 한 번** 묻는다: "`awesome-ai-motion` 스킬도 함께 쓸까요?" (CLAUDE.md 8번). 승낙해도 이 스킬의 시각 규칙이 우선이다.
- 결과물은 `~/Desktop/cysjavis/<주제폴더>/<한글이름>/`에 만든다(정본: `발표.html`, 음성 `audio/`, 사진 `img/`, 최종 `발표.mp4`). 아티팩트로 올리면 그건 사본이다.
- 통계는 출처 있는 값만 쓴다. 없으면 라벨에 "(예시)"를 붙인다.
- 목소리 클론·유료 생성(ElevenLabs, 이미지·영상 생성)은 비용이 든다. **처음 호출 전에 한 번** 비용과 계정을 확인받는다(파괴적·대외적 행위 예외).

## 1. 제작 파이프라인 (영상이 실제로 쓴 순서)

영상의 핵심 원칙 두 가지: **사람은 대본과 판단, 반복은 에이전트.** 그리고 **장면 길이는 글자 수가 아니라 실제 음성 길이로 정한다.**

| 단계 | 영상에서 쓴 도구 | 여기서 쓰는 것 |
|---|---|---|
| 1. 대본 | ChatGPT와 대화하며 사람이 씀 | 사용자 원고. 원문에 없는 내용·숫자는 만들지 않는다 |
| 2. 장면 분할 | VideoGen이 대본을 장면(shot)으로 나눔. 92장면 / 11분 ≈ **장면당 7초** | 이 스킬 2절 규칙으로 직접 나눈다 → `shots.json` |
| 3. 더빙 | ElevenLabs v4 클론 음성, **문단별 생성**, 발음 사전(“클로드”→“클로우드”) | `voice-clone-elevenlabs` 스킬(없거나 거절 시 `voicebox-local-tts`, 그것도 안 되면 무음 + 자막). 문단별 `audio/n001.mp3…`. 어색한 문단만 다시 생성 |
| 4. 화면 녹화 | Aside CLI가 브라우저를 직접 열고 조작·캡처 | 실제 시연이 필요하면 내장 브라우저로 조작 후 화면 녹화. **민감 정보(계정·키)가 화면에 안 나오게** 범위를 먼저 정한다 |
| 5. 연출 클립 | Grok Imagine. 스타일 앵커 1장 → 무대 → 첫 프레임 → 짧게 움직임 | `media-gen-image` / `media-gen-video` 스킬. 클립 소리는 끄고(audio track 0), 전체 러닝타임의 **30~40% 이하**만 생성 클립 |
| 6. 배치·자막 | 실제 음성 길이 기준으로 장면·자막 배치, 문장 겹침·누락 검사 | template.html의 `data-audio`로 박자 = 음성 길이. 자막도 같은 시간축 |
| 7. 렌더 | Remotion → MP4 | ① HTML `?auto=1` 화면 녹화(가장 빠름) ② MP4 직접 렌더는 `remotion-kr`·`video-stitch` 스킬로 넘긴다 |
| 8. 검수 | 사람: 클론 발음, 장면 전환 타이밍 | `video-verify` 스킬(싱크·타이밍·시각) 후 사용자에게 발음·전환만 확인받는다 |

영상 결과 참고치: 대본 4,700자 → 89문단 · 92장면 · 생성 클립 30개(17개 재생성) · 첫 완성본까지 1시간 42분 · 92장면 중 69개 첫 생성본 그대로 사용.

## 2. 장면 설계 규칙

- **장면 = 대본 한 문단 = 5~10초.** 장면마다 제목 칩 하나. 칩 문구는 그 문단을 12~22자로 압축한 헤드라인이고, **핵심어 1~2개만** `<b>`로 감싼다.
- 칩 문형(영상에서 반복된 것): `A — B`(대시로 대비), `A ≠ B`, `A → B`, `A vs B — 차이는?`, `① 도구명 — 하는 일`(단계 번호), `숫자 <b>N개</b> 처음 그대로`.
- **장면 3종을 번갈아 쓴다.** 같은 종류가 3장 넘게 연속되지 않게.
  - **사진 무대(photo)**: 감정·도입·전환·결론. 실사풍 AI 배경 + 같은 인물 전신. 위에 떠 있는 라벨·필·손글씨. 비율 약 35%.
  - **크림 도식(light)**: 개념·과정·비교·숫자. 비율 약 40%.
  - **네이비 화면(dark)**: 실제 터미널·코드·웹 시연 캡처. 비율 약 25%.
- 한 박자(자막 한 줄)에 새로 등장하는 요소는 1~3개. 장면당 박자 2~5개.
- 결론부는 **사진 + 붓글씨 한 단어**(예: “생각”), 마지막은 **+1 · NEXT QUESTION · 명조 질문**으로 다음 편 예고.

### 글꼴
- **Pretendard** — 칩 33px/700(키워드 800), 라벨 22~26px/700, 큰 숫자 150~300px/900 `tabular-nums`.
- **JetBrains Mono** — 터미널, `PROMPT`, `NEXT QUESTION`, 모델명 필(`model · eleven_v4`), 파일 경로. 대문자 라벨은 자간 .12~.2em.
- **나눔펜(Nanum Pen Script)** — 손글씨 주석(코럴 또는 잉크), 살짝 기울임 −4~−6°. “내 귀로 확인”, “말이 끝나기 전에 다음 컷” 같은 혼잣말.
- **나눔붓(Nanum Brush Script)** — 결론 한 단어, 흰색, 사진 위 180px 이상.
- **Noto Serif KR** — 마무리 질문 한 곳만.

### 제목 칩 (= 자막. 영상의 시그니처)
- 상단 중앙, 위에서 46px. 흰 바탕, 1.5px 잉크 테두리, 모서리 4px, 높이 84px, 왼쪽 노란 막대(6×34px).
- 장면이 바뀔 때마다 **글자당 55ms 타자 입력**(깜빡이는 커서) → 다 쳐지면 키워드가 **검은 칩 + 흰 글씨**로 바뀌고 **노란 밑줄이 왼→오로 그어진다**.
- 하단 자막은 원본에 없다. 필요하면 `?subs`로 켜는 하단 반투명 박스(36px/600, 한 줄)를 쓴다.

### 부품
- **필(pill)**: 반투명 검정 알약 + 틸 점 + 흰 글씨, 틸 외곽선. 사진 위 도구명·라벨(“● Claude Code”, “● 샘플 ≈ ● 내 녹음”).
- **태그**: 흰 사각 라벨(사진 위 설명), 코럴 태그는 기울여 경고(“사용 중단”, “전부 AI 클립?”).
- **카드**: 잉크 2px 테두리, 반경 14px, 그림자, **±3~4° 기울임**. 안에 틸 라벨 + 회색 막대.
- **노드 타임라인**: 회색선 위 흰 원(테두리), 시작점만 코럴 채움, 끝에 검은 `?` 깃발이 떨어진다.
- **터미널 창**: 맥 점 3개, 모노 제목(“메인 세션 — Claude Code · 실제 기록”), 강조 줄은 노란 반투명 띠, 체크는 틸. 옆에 상태 필과 큰 노란 숫자 `53 / 89` + 진행 막대.
- **큰 숫자 + 형광펜 + 와플**: 손글씨 라벨 → `69 / 92`(뒤에 형광펜 띠) → 틸로 채워지는 칸 / 노란 테두리 빈칸.
- **프롬프트 박스**: `PROMPT ●○○` 머리 + 52px 굵은 문장 타이핑, 아래 빈 입력줄 `>`.
- **사물 일러스트**: 마이크·노트북·종이·필름릴·저울 같은 반실사 3D 오브젝트를 크림 바닥에 그림자와 함께. 생성 이미지로 만든다.

## 4. 사진 무대 만들기 (AI 이미지)

영상 방식 그대로 **스타일 앵커 → 무대 → 첫 프레임** 순서로 만들어 인물·조명이 장면마다 같게 유지한다.
1. **스타일 앵커 1장**: “photorealistic, warm natural window light, cozy Scandinavian interior with plants and wooden floor, 35mm, soft depth of field, muted warm palette, 16:9”.
2. **무대 배경 몇 장**(녹음 부스, 서재, 사무실, 강당, 서버실, 스튜디오, 도시 노을) — 앵커와 같은 조명·색.
3. **인물**: 같은 사람을 정면 전신으로(영상은 회색 후드티 + 검정 바지 + 흰 운동화의 발표자, 보조로 회색 재킷의 여성). 사용자 본인 사진을 쓰면 그 사진을 기준으로.
4. 인물은 화면 가운데 또는 1/3 지점, **위쪽 140px은 칩 자리라 비운다.** 라벨·카드는 인물 옆 빈 공간에 띄운다.
5. 움직임이 필요하면 첫 프레임에서 5~6초 클립(`media-gen-video`)을 만들고 소리를 뺀다. 클립 대신 정지 사진 + 켄번스로도 충분하다.
- 생성 도구를 못 쓰면 template의 그라데이션 자리표시를 그대로 두고, 프롬프트 목록을 `img/프롬프트.md`로 남긴다.

## 5. 절차

1. **원문 읽기** → 문단 단위로 나눈다. 문단 = 장면.
2. **`shots.json` 작성**: 장면마다 `{id, type: photo|light|dark, chip, beats:[자막 줄…], visual: 설명, audio: "audio/n001.mp3"}`.
3. **(동의 시) 음성 생성**: 문단별 mp3. 발음 사전(영문 고유명사·숫자 읽기)을 먼저 만든다. 길이 확인:
   `for f in audio/*.mp3; do printf "%s " "$f"; ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"; done`
4. **template.html 복사 → 장면 채우기**: `<section class="slide">` 블록을 복사해 `data-chip`, 요소, `data-*` 박자만 바꾼다. `<ol class="subs">`의 `<li>` 수가 박자 수다. 음성이 있으면 각 `<li data-audio="audio/n001-1.mp3">`(문장 단위) 또는 장면 첫 `<li>`에 문단 mp3를 달고 나머지는 `data-ms`로 나눈다.
5. **검증**: 브라우저로 열어 키로 끝까지 넘긴다 — 칩 한 줄 넘침 없음, 칩과 요소 겹침 없음, 같은 장면 종류 3연속 없음, 콘솔 오류 없음. 그다음 `?auto=1`로 한 번 통째로 돌려 음성과 화면이 어긋나지 않는지(말이 끝나기 전에 장면이 넘어가지 않는지) 본다.
6. **영상화**: `?auto=1`로 열고 화면 녹화(QuickTime/OBS, 1920×1080) — 힌트는 자동으로 숨는다. MP4를 직접 렌더해야 하면 `remotion-kr`로 넘긴다(같은 토큰·박자표를 그대로 옮긴다).

## 6. 조작

`→`/스페이스/클릭 다음 박자 · `←` 이전 · `S` 하단 자막 · `F` 전체화면 · `?auto=1` 자동재생(음성 길이 기준) · `?subs` 하단 자막 켜기 · `?rec` 힌트·사진 자리 안내 숨김.

## 7. 하지 말 것

- 칩 없이 장면 시작, 칩 두 줄, 키워드 3개 이상 강조.
- 틸·노랑·코럴 말고 다른 강조색, 화려한 그라데이션 배경(사진 장면 제외), 회전·플립 전환.
- 장면 길이를 글자 수로만 추정해서 음성보다 먼저 넘기기.
- 영상 전체를 생성 클립으로 채우기(실제 시연·도식이 중심, 생성 클립은 필요한 곳만).
- 발표자 사진·목소리를 본인 동의 없이 남의 것으로 만들기.

## 언제 어느 단계를 쓰나

사용자가 단계를 지정하지 않으면 지금 시점을 보고 하나만 실행한다. 긴 점검표를 한꺼번에 들이밀지 않는다.

### A. 맡기기 전 (작업 지시 직후, 실행 전)
1. 위험도 분류: "틀려도 별일 없음"이면 통째로 맡긴다고 한 줄 알리고 진행. "결과를 책임져야 함"(돈·대외 발송·설교·공문·배포)이면 아래 2~3을 한다.
2. 빈칸 세 개를 확인한다: **누구를 위한 것인지 / 하지 말아야 할 것 / 어디까지 하면 끝인지.** 빠진 것만 한 번에 묻는다. 사용자가 정리가 안 됐다고 하면 grill-me로 넘긴다.
3. "실행 전에 예상 답을 한 줄 적어 두시겠어요?"라고 한 번 제안한다(강요 금지). 적으면 `python3 ~/Desktop/cysjavis/AI동향_검토/AI결과물_내것만들기_7가지_JayChoi_2026-11-15/실습키트/판단일지.py 예상 "과제" "예상"`으로 기록한다.

### B. 진행 중
- 스스로 확인할 수단(테스트·스크린샷·원본 대조)을 먼저 정하고 그걸로 고치기를 반복한다.
- 테스트를 직접 만들었다면 "테스트가 같은 가정을 공유하는지"를 한 줄로 밝힌다.

### C. 끝난 뒤 — 결정 보고 (이 스킬의 핵심)
완료 보고 맨 앞에 요약 대신 다음 순서로 쓴다.
1. **실제로 실행한 것과 결과**: 명령·건수·통과/실패 원문 그대로.
2. **내가 대신 정한 것**: 기본값, 범위, 여러 선택지 중 고른 것. 각 1줄 + 다른 선택지 1개.
3. **내가 가정한 것**: 확인하지 않고 전제한 사실.
4. **확인 못 한 것**: 사용자가 직접 열어 볼 원본 2~3개를 콕 집어 준다(요약 작업이면 원본 표본 링크).
5. 사용자가 "내가 놓친 거 있어?"라고 물으면, 사용자가 묻지 않은 위험·반례·대안을 3개 이내로 말한다.

### D. 별로였을 때 — 규칙으로 남기기
사용자가 결과를 별로라고 하면 다시 만들기 전에 "왜 별로인지"를 한 문장으로 같이 정리하고 판단일지에 `대조 번호 다름|틀림 "메모" "왜 별로"`로 남긴다. `판단일지.py 규칙`에서 **두 번 이상 반복된 것만** CLAUDE.md·스킬 후보로 제안한다(사용자 CLAUDE.md 원칙: 두 번 이상 틀린 것만 적는다). CLAUDE.md는 사용자 승인 없이 고치지 않는다.

## 하지 않는 것
- 사용자의 이해를 '검사'처럼 다루지 않는다. 목적은 사용자의 이해를 넓히는 것.
- 생산량이 사용자가 확인할 수 있는 양을 넘으면 에이전트를 더 돌리자고 하지 않는다. 확인 기준을 촘촘히 하거나 단위를 줄이자고 제안한다.

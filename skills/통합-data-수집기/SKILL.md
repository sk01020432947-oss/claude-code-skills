# 통합 DATA 수집기 만들기

흩어진 개인 자료를 **한 파일(`통합자료.jsonl`)** 로 모으고 **한 화면(`…수집기.html`)** 에서 찾아 쓰게 만드는 도구를 짓는 방법이다. 2026-11 에 KBG-통합자료수집기를 실제로 만들면서 굳어진 순서와 규칙을 그대로 적었다.

## 먼저 판단한다 — 새로 짓나, 있는 것을 고치나

1. `~/Desktop/cysjavis/SNS_기록/통합수집기/통합정리.py` 가 있으면 **그것이 정본**이다. 새로 짓지 말고 그 폴더에서 고친다(그 폴더의 `CLAUDE.md` 가 최신 사용법이다). 이 스킬의 `assets/` 는 2026-11-14 스냅숏이라 정본보다 낡았을 수 있다.
2. 정본이 없거나(다른 컴퓨터·다른 사람), 사용자가 "하나 더"를 원하면 `assets/` 를 새 폴더에 복사해 아래 "새로 지을 때" 순서로 맞춘다.
   정본에 큰 기능을 더한 뒤에는 이 스킬 폴더에서 `python3 묶기.py` 로 스냅숏을 새로 뜬다(코드 11개만 베끼고, 정본과 같은지·자료 파일이 섞이지 않았는지 확인한다). 새 기능에서 배운 함정이 있으면 아래 "함정" 절에 한 줄 더한다.
3. 어느 쪽이든 고친 뒤에는 "점검" 절을 끝까지 돈다. 산출물이 있다고 끝이 아니다 — 화면이 실제로 뜨는 것까지 본다.

## 전체 구조 (세 덩어리)

```
① 모으기                      ② 합치기·저장                 ③ 보기
북마클릿(브라우저, 로그인 화면) ─┐
파일·주소를 직접 읽는 수집 함수 ─┼→ 통합정리.py → 통합자료.jsonl → …수집기.html (단일 파일)
폴더에 둔 파일·연결한 디스크   ─┘        ↑                              │
                                  메모태그.json ←── 다운로드 폴더의 tonghap_memo_*.json ←┘
```

- **글 한 건의 모양은 하나뿐이다**: `{platform, id, author, url, date, title, text}`. 모든 수집 함수는 `rec(platform, id, text, author, url, date, title)` 로 이 모양을 만들어 돌려준다. 출처가 늘어도 뒤쪽(합치기·화면)은 손대지 않게 하려는 것이다.
- **중복 판정은 `(platform, id)`**. 같은 글이 또 들어오면 본문이 긴 쪽을 남기고 빈 칸은 서로 채운다(`merge`). 그래서 "여러 번 돌려도 같은 글은 한 번만"이 성립한다 — id 는 다시 수집해도 안 변하는 값(글 주소·파일 경로·아티팩트 주소)으로 잡는다.
- **화면은 파이썬 문자열 `PAGE` 하나**다. `save()` 가 `__SUB__ __DATA__ __NOTES__ __NAME__ __AUTO__ __BUILD__ __DISKS__` 자리를 채워 HTML 한 파일로 쓴다. 서버·빌드 도구·외부 글꼴·외부 스크립트가 없다 — 더블클릭으로 열리고, 인터넷이 없어도 되고, 남의 글이 밖으로 나갈 길이 없다.
- **화면 → 파일 길은 "내려받기" 하나**다. 브라우저는 디스크에 못 쓰므로, 화면에서 고친 메모·태그·별표·삭제 표시·직접 추가한 글은 우선 localStorage 에 두고 「메모 파일로 저장」이 다운로드 폴더에 `tonghap_memo_*.json` 을 떨어뜨린다. 다음 실행이 그것을 `메모태그.json` 에 합친다(같은 글은 나중에 고친 쪽, `t` 값 비교).
- 화면용 덧칸 `k`(주제) `o`(출처) `s`(저장소 줄) `i`(그림 주소)는 **화면에만 붙이고 jsonl 에는 안 넣는다.** 분류 규칙을 고치면 다음 실행 때 전부 다시 매겨지게 하려는 것이다.

파일별 역할과 `통합정리.py` 안의 자리는 `references/구조.md`, 기능별 사용법 전문은 `references/기능명세.md` 에 있다. 기능을 고칠 때는 그 기능의 줄을 `기능명세.md` 에서 먼저 찾아 읽는다.

## 만든 순서 (이 순서로 지으면 매 단계가 혼자서도 쓸모 있다)

각 단계는 "사용자가 한 마디 하면 Claude 가 돌리고 건수만 보고한다"로 끝나야 한다. 사용자는 비개발자다.

| 단계 | 만드는 것 | 핵심 결정 |
|---|---|---|
| 1 | **한 사이트용 북마클릿**(`수집기.js`) + 파싱(`parse_manual.py`) + 검토 화면(`make_review_page.py`) | 사용자가 직접 연 화면의 글자를 옮겨 적기만 한다. 눌러도 바로 안 달리고 [▶ 시작]을 기다린다. 금지 규칙 6개(아래) |
| 2 | **여러 사이트용 북마클릿**(`통합수집기.js`) | `SITES = {threads, x, instagram, facebook, etc}` — 사이트마다 `read()` 만 다르다. `sns_*posts*.json` 으로 내려받는다. 가짜 화면 `수집기_점검.html` 로 점검 |

| 8 | **옵시디언으로 보내기** | 볼트의 대기실 폴더에 새 노트만. 있던 노트는 안 건드린다 |

| 10 | **폰 자료** — `폰자료/` 폴더 파일, (맥이면) 메시지·통화·메모·사진 앱 | 폴더 길은 자동, 앱 자료 길은 사용자가 말할 때만 |

## 지킬 것 (타협하지 않는다)

이 도구에는 **남이 쓴 글·대화·개인 사진**이 들어간다. 아래는 편의가 아니라 그것을 지키는 선이다.

- **로그인 자동화·차단 우회를 만들지 않는다.** SNS 수집은 사용자가 직접 로그인해 연 화면에서 북마크를 눌렀을 때만 한다. 북마클릿은 `fetch` 를 하지 않는다 — 화면에 보이는 글자를 옮겨 적을 뿐이다.
- **Claude 는 자료를 컴퓨터 밖으로 올리거나 보내지 않는다.** `통합자료.jsonl`, 보기 화면 HTML, `사진미리보기/`, 옵시디언으로 보낸 노트 폴더 모두 해당한다. 밖으로 꺼내는 길은 화면의 「⇪ 내보내기·공유」를 **사용자가 직접 누르는 것** 하나다. 아티팩트·깃 저장소·메일·클라우드에 올리자는 생각이 들면 멈추고 묻는다.
- **화면은 밖과 통신하지 않는다.** 외부 글꼴·스크립트·분석 코드 없음. 예외는 둘뿐이고 둘 다 문서에 적혀 있다: 자기 폴더의 `tonghap_build.js`(판 번호 한 줄), 사용자가 「🖼 그림 N 보기」를 눌렀을 때의 그 한 장.
- **남의 글은 `textContent` 로만 넣는다. `innerHTML` 금지.** 수집한 글에 태그가 섞여 있어도 실행되지 않게 하려는 것이다. 자료를 `<script>` 안에 실을 때는 `</` 를 `<\/` 로 바꾼다.
- **비밀번호·인증서·카드·은행 자료는 가져오지 않는다.** 디스크를 훑을 때 `NPKI`·`GPKI`·`신분증` 폴더와 숨김·시스템 폴더는 건너뛴다. 잠근 메모·가린 사진도 건너뛴다.
- **있던 것을 고치지 않는다.** 옵시디언 노트는 읽기만 하고 새 노트는 대기실 폴더에만 만든다. 디스크의 파일은 이름만 읽는다. 원본 앱 DB 는 읽기 전용으로 연다.
- **시스템·폰 설정은 사용자가 바꾼다.** 권한 허용, iCloud 켜기, USB 디버깅 같은 것은 안내만 한다.
- **모인 만큼만 정리한다.** 부족하면 "자료 부족"이라고 적는다. 억지로 채우지 않는다.
- **알림·토스트에는 건수만.** 제목·이름·내용을 띄우지 않는다. 대화로 보고할 때도 남의 이름·통화 상대·사진 내용·디스크 폴더 이름은 옮기지 않는다.

## 북마클릿 금지 규칙 6개 (전부 실제 사고에서 나왔다)

1. `MutationObserver` 금지 — 패널을 다시 그리는 것을 스스로 감지해 무한 반복, 탭이 멈췄다. 일정 간격으로 훑는다.
2. 패널은 `body` 가 아니라 `documentElement` 에 붙인다 — 사이트가 body 를 갈아 끼우면 패널이 사라진다.
3. 화면 갱신은 `textContent` 만 바꾼다(innerHTML 통째 교체 금지).
4. localStorage 백업은 띄엄띄엄(스로틀) — 글마다 쓰면 느려진다.
5. `%` 글자와 나머지 연산자를 쓰지 않는다 — 북마클릿 URL 안에서 `%60` 같은 것이 인코딩으로 잘못 풀려 코드가 깨진다.
6. `render()` 에서 패널 크기를 바꾸지 않는다 — 상자가 커졌다 작아졌다 하면 단추를 못 누른다.

`.js` 를 고치면 북마클릿 txt 를 **반드시 같이** 다시 만든다. 둘이 따로 놀면 사용자는 옛 코드를 누르게 된다.

```bash
bun build 통합수집기.js --minify --target=browser   # 결과를 한 줄로(줄바꿈은 \n), 앞에 javascript: 를 붙인다. 결과에 % 가 있으면 안 된다
```

## 함정 (같은 데서 두 번 넘어지지 않게)

- **`PAGE` 는 raw 가 아닌 삼중따옴표 문자열**이다. 그 안의 JS 역슬래시는 파일에서 두 번(`\\n`, `\\/`) 써야 한다.
- **JS 최상위 이름이 겹치면 화면이 통째로 멈춘다.** 새 `const/let/function` 을 넣기 전에 그 이름을 grep 한다(`PER`, `step` 으로 두 번 깨졌다). selfcheck 가 `node --check` 로 잡아 주지만 node 가 없으면 못 잡는다.
- **selfcheck 를 파이프에 물리지 않는다.** `selfcheck | tail -1 && --all` 은 실패를 가려서 깨진 화면을 그대로 다시 만든다. `python3 통합정리.py --selfcheck && python3 통합정리.py --all` 처럼 종료 코드를 직접 본다.
- **`confirm()` `alert()` `prompt()` 를 쓰지 않는다.** 앱 안 브라우저에서는 창이 안 뜨고 곧바로 "아니오"가 돼 삭제가 조용히 안 먹었다. 묻는 창은 `<dialog>` 로 화면 안에 띄운다.
- **맥의 한글 파일 이름은 NFD(자소 분리)다.** 셸 글롭·grep 이 어긋난다. 한글 경로는 python3 으로 다루고, 비교·표시 전에 `unicodedata.normalize("NFC", …)` 한다.
- **큰 자료는 한 번에 그리지 않는다.** 카드는 한 쪽 20건, 사진 바둑판은 한 쪽 500장, 왼쪽 칸 출처는 큰 것 40곳만. 디스크는 `islice` 로 상한을 두고 넘으면 "더 작은 폴더로 나눠 연결"을 안내한다.
- **화면이 파이썬을 부르는 길은 신호 파일뿐**이다(`tonghap_now_*.json` 을 내려받게 하고 LaunchAgent 가 다운로드 폴더를 지켜본다). 신호에 실려 온 경로는 믿지 않는다 — 디스크 연결은 `/Volumes` 아래만 받는다.
- **자동 수집과 수동 실행이 겹치면 파일이 깨진다.** `.lock` 으로 한 번에 하나만.
- **열려 있는 화면을 함부로 새로 고치지 않는다.** 판 번호가 바뀌어도 사용자가 무언가 고르거나 거르는 중이면 "새 자료가 들어왔습니다 — 눌러서 새로 고침"만 띄운다.
- **`file://` 그림은 `http://` 로 띄운 화면에서 안 보인다.** 사진 확인은 HTML 을 파일로 직접 열어서 한다.
- **패치는 "정확히 한 곳"을 확인하고 한다.** `통합정리.py` 는 2,000줄이 넘는다. 바꿀 문자열마다 `s.count(old) == 1` 을 확인하는 파이썬 치환으로 고치면 엉뚱한 곳이 바뀌지 않는다.
- **사진 앱 사진은 브라우저가 못 읽는다.** 사진 앱이 만들어 둔 미리보기 jpeg 를 `사진미리보기/<id>.jpg` 로 베껴 두고 그린다.

## 새로 지을 때 (다른 컴퓨터·다른 사람)

1. `assets/` 의 파일을 새 도구 폴더로 복사한다. `references/기능명세.md` 를 그 폴더의 `CLAUDE.md` 로 복사하고 경로·이름을 새 사용자에 맞춘다.
2. `통합정리.py` 맨 위 설정을 맞춘다(`references/구조.md` 의 "설정" 표): `VIEW` 파일 이름, `VAULT_INBOX`·`VAULT_AUTHOR`·`INBOX_DIRS`(옵시디언이 없으면 비운다), `BM_SHELVES`, `TOPICS`, `AGENT` 이름표, `ARTIFACTS`, `KAKAO_PY`·`NAVER_PY`.
3. 딸린 것을 확인한다: `python3`(표준 라이브러리만 쓴다), `node`(selfcheck 문법 검사, 없으면 건너뛴다), `bun`(북마클릿 다시 만들 때만), `yt-dlp`(유튜브 쓸 때만). 카톡은 `assets/곁도구/카카오톡_자료정리.py` 를 `KAKAO_PY` 자리에 둔다. 아티팩트 장부 훅은 `assets/곁도구/artifact-ledger.py` — 설치는 사용자 승인 후 `settings.json` 의 PostToolUse(Artifact)에.
4. 맥이 아니면: 자동 수집(`agent()` — LaunchAgent)과 폰 앱 자료(`from_phone()`), `/Volumes` 는 맥 전용이다. 윈도우·리눅스에서는 그 셋을 그 OS 의 것(작업 스케줄러·systemd, 드라이브 문자·`/media`)으로 바꾸거나 빼고 `폰자료/` 폴더 길과 수동 실행만 남긴다. 나머지는 그대로 돈다.
5. `python3 통합정리.py --selfcheck` → 북마클릿을 브라우저 북마크로 등록(사용자가) → 사용자가 SNS 화면에서 한 번 수집 → `python3 통합정리.py --all --open`.
6. 사용자가 원할 때만 `--auto-on`. 출처는 한꺼번에 다 켜지 말고 사용자가 쓰는 것부터 하나씩 — 건수를 보고 다음으로 간다.

## 출처 하나 더하는 법

1. `from_○○()` 함수를 쓴다 — `rec("○○", 안 변하는 id, 본문, 글쓴이, 주소, 날짜, 제목)` 의 목록을 돌려준다. 못 읽은 것은 건너뛰고 건수를 `print` 한다(실패 하나로 전체가 멈추면 안 된다).
2. `LABEL["○○"] = "화면 이름"`.
3. `main()` 에 옵션 한 줄과 `--all` 에 넣을지 한 줄. 자동으로 지켜볼 파일이면 `stamp()` 와 `agent()` 의 감시 목록에도.
4. 왼쪽 칸에서 묶어 보이려면 화면 코드의 `GRP` 한 줄(`phone_*` → 스마트폰, `threads*` → 쓰레드, `disk_*` → 연결이 그 예).
5. `selfcheck()` 에 임시 폴더로 만든 가짜 자료 한 벌과 `assert` 몇 줄.
6. 폴더 `CLAUDE.md` 에 "무엇을 읽고 무엇은 안 읽는지" 한 줄.

## 점검 (고칠 때마다, 이 순서로)

```bash
python3 통합정리.py --selfcheck
```

```bash
python3 통합정리.py --all
```

1. selfcheck 가 `selfcheck OK` 로 끝나고 종료 코드가 0 인지 **직접** 본다.
2. 다시 만든 뒤 건수가 줄지 않았는지 본다(줄었으면 삭제 반영인지 사고인지 가린다).
3. 화면을 띄워 콘솔 오류가 없는지, 고친 기능을 한 번 눌러 본다. 사용자가 그 화면을 쓰고 있을 수 있다 — 시험은 최소로 하고, 고르거나 지운 상태를 원래대로 돌려놓는다. 사용자의 localStorage 에는 아직 파일로 안 내린 메모·삭제 표시가 있을 수 있다.
4. `.js` 를 고쳤으면 북마클릿을 다시 만들고 `수집기_점검.html` 을 열어 "전부 통과"를 본다.
5. 사용자에게는 **건수와 바뀐 점만** 쉬운 말로 알린다. 확인하지 못한 것(실제 SNS 화면, 사파리, 실제 디스크에서 단추 누르기 등)은 못 했다고 그대로 적는다.

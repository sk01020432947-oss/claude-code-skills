# YouTube Study Fit — 영상 학습 + 나에게 맞는지 점검

목적은 요약이 아니라 **판단**이다. "이 영상의 내용을 내 일에 들일 것인가, 어떻게, 스킬로 굳힐 것인가"에 답하는 학습 노트를 만든다.

## 0. 원칙

- **본 것만 쓴다.** 자막·설명·신뢰할 만한 정리 자료로 확인한 내용만 "영상에서"라고 쓴다. 확보 못 한 영상은 "미확인"으로 남기고 내용을 지어내지 않는다.
- **출처 수준을 표시한다.** 각 영상마다 근거가 `자막 전문` / `설명란·요약` / `제3자 정리` 중 무엇인지 노트에 적는다.
- **사용자 맥락으로 판단한다.** 일반론의 "좋다"가 아니라, 사용자의 기존 스킬·업무에 비추어 필요도를 매긴다.

## 1. 자료 확보 (위에서부터 되는 것 하나)

여러 링크가 오면 먼저 영상 ID를 모두 뽑아 표로 만든다 (`v=` 값, `youtu.be/` 뒤 11자, `&t=` 는 버림).

1. **yt-dlp 자막** (로컬 PC에서 가장 확실)
   ```bash
   yt-dlp --skip-download --write-auto-subs --write-subs --sub-langs "ko,en" \
          --sub-format vtt -o "%(id)s.%(ext)s" "<URL>"
   yt-dlp --skip-download --print "%(title)s|%(channel)s|%(duration_string)s|%(upload_date)s" "<URL>"
   ```
   VTT는 타임스탬프와 중복 줄을 걷어 내고 본문만 남긴다.
2. **insane-search 스킬**이 설치돼 있으면 그쪽의 YouTube 경로를 쓴다.
3. **웹 검색**으로 영상 ID·제목을 찾는다. 같은 영상을 정리한 블로그나 공개 저장소(영상 노트)가 있으면 근거로 쓰되 `제3자 정리`로 표시한다.
4. 모두 막히면(클라우드 세션의 네트워크 차단 등) 사용자에게 **YouTube "스크립트 표시" 텍스트를 붙여 달라**고 요청한다. 확보된 영상만으로 먼저 진행한다.

## 2. 묶기

영상이 여러 개면 주제를 본다. 같은 주제(예: 같은 도구를 다룬 영상들)면 **하나의 통합 노트**로, 다르면 주제별로 노트를 나눈다. 추천 시청 순서(입문 → 활용 → 심화)를 정한다.

## 3. 사용자 맥락 파악

- `~/.claude/skills/` (또는 저장소의 `skills/`)의 스킬 이름과 description을 훑어 사용자의 업무 영역을 3~5개로 요약한다.
- 영상 주제와 겹치거나 이어지는 기존 스킬을 찾아 둔다. 이 목록이 6장(필요도)과 9장(스킬화 점검)의 근거가 된다.

## 4. HTML 노트 구성

한 파일짜리 HTML로 만든다 (외부 스크립트 없이, 라이트·다크 모드, 모바일 폭 대응). 저장 위치는 `학습노트/<주제-슬러그>.html`.

| 장 | 내용 |
|---|---|
| 0. 영상 목록 | 제목·채널·길이·날짜·근거 수준·한 줄 요약·추천 순서 |
| 1. 한 장 요약 | 핵심 문장 1개 + "언제 쓰나" 판별 한 줄 + 흐름도 |
| 2. 개념 | 기존 방식과 비교표 (무엇이 새롭나) |
| 3. 핵심 내용 | 기능·절차·팁 표 (영상 타임스탬프가 있으면 링크) |
| 4. 실전 적용 | 사용자가 쓰는 도구(예: Claude Code)와 붙이는 구체 절차·명령 |
| 5. 위험과 비용 | 요금, 보안, 알려진 실패 사례 |
| 6. 나에게 필요한가 | 영역별 필요도(높음/중간/낮음) 표 + **결론 박스** + 왜·효과(가능하면 시간 절감 계산, 가정임을 표시) |
| 7. 확장 응용 | 사용자의 기존 스킬과 연결한 아이디어 4~6개 |
| 8. 실천 과제 | 하루 10분 × 1~2주 체크리스트 + 끝났을 때 자기 점검 3문항 |
| 9. 스킬화 점검 | 후보별 판정표 (❌ 불필요 / △ 시험 후 / ✅ 생성) + 이유 |
| 10. 퀴즈 | `<details>` 로 접은 능동 회상 문제 5~7개 |
| 참고 자료 | 영상 링크 + 사용한 근거 자료 링크 |

## 5. 스킬화 판정 기준

| 판정 | 조건 |
|---|---|
| ❌ 불필요 | 일회성 지식이거나, 기존 스킬·도구가 이미 덮는다 |
| △ 시험 후 | 반복될 가능성은 있으나 절차가 아직 검증되지 않았다 → "같은 일이 두 번 통하면 굳힌다" |
| ✅ 생성 | 같은 절차를 사용자가 이미 반복하고 있고, 입력·출력 형태가 정해져 있다 |

✅ 판정이면 `skills/<name>/SKILL.md` 초안을 실제로 만들고, 기존 스킬과 이름·발동 문구가 겹치지 않는지 확인한다.

## 6. 마무리 보고

채팅에는 짧게: 확보한 영상/못 한 영상, 결론(필요한가) 한 줄, 스킬화 판정 한 줄, HTML 경로. 노트 본문을 채팅에 다시 붙이지 않는다.

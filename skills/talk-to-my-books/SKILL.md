# Talk to My Books — 내 자료와 대화

사용자의 모든 자료(책, 설교, 주석, 강의안)를 「책 속에 살아있는 대화」 형식으로 변환해 대화하는 스킬.
참조 모델: talk-to-algorithms.vercel.app (책 소개 카드 + 책 지도 + 예시 질문 + 본문 근거 답변).

**서재 위치**: `C:\Users\ASUS\Documents\talk-library\`
서재 목록은 `talk-library\INDEX.md`. 책 하나 = 폴더 하나(slug).

```
talk-library/
  INDEX.md              # 등록된 책 목록 (제목·slug·분량·등록일)
  <slug>/
    book.json           # 메타: title, author, intro, stats, sample_questions[]
    map.md              # 책 지도: 장별 제목 + 요약 1줄 + 원문 파일 경로
    text/               # 변환된 원문 (장 단위 md: 01-<장제목>.md ...)
```

## 모드 판별

- 경로/파일을 주며 등록·변환·학습을 요청 → **등록 모드**
- 책 이름을 대며 질문하거나 "서재", "대화" 요청 → **대화 모드**
- 책 이름 없이 대화 요청 → INDEX.md를 읽어 서재 목록을 보여주고 고르게 한다

## 등록 모드 (자료 → 대화용 책)

### 1. 수집·변환
받은 경로의 파일 형식을 확인하고 md로 변환한다. 변환물 외 원본은 건드리지 않는다.

| 형식 | 방법 |
|------|------|
| .md / .txt | 그대로 사용 |
| .hwp / .hwpx | kordoc MCP (`parse_document` → markdown) |
| .pdf | `pdftotext -enc UTF-8 -layout in.pdf out.txt` |
| .docx | anthropic-skills:docx 스킬 또는 pandoc |

폴더를 받으면 안의 문서 전체를 하나의 책으로 묶는다(예: 설교 원고 폴더 → "설교집").
파일이 많으면 파일명·수정일 순으로 정렬해 회차/장 순서를 정한다.

### 2. 장 분할 + 책 지도
- 변환된 원문을 논리 단위(장/설교 1편/주제)로 나눠 `text/NN-제목.md`로 저장. 원문 텍스트는 **한 글자도 수정하지 않는다** — 분할과 파일명 부여만 한다.
- `map.md` 작성: 각 장마다 `NN장 제목 — 핵심 요약 1줄 → text/NN-제목.md`
- 분량 통계 산출(총 자 수, 장 수)

### 3. book.json + 예시 질문
```json
{
  "slug": "...", "title": "...", "author": "김병곤",
  "intro": "저자와 책 소개 2~3문장 (사이트의 소개 카드에 해당)",
  "stats": { "chapters": 13, "chars": 250000, "registered": "YYYY-MM-DD" },
  "sample_questions": ["...", "... (6~8개)"]
}
```
예시 질문은 실제 본문을 훑어 **그 책이 답할 수 있는 질문만** 만든다. 난이도 섞기(입문 2, 핵심 3, 심화 2).

### 4. 서재 등록 + 확인
- `INDEX.md`에 한 줄 추가: `- [제목](slug/map.md) — 장수·분량·등록일`
- 완료 보고: 아래 "첫 화면" 형식으로 등록된 책을 바로 보여준다.

## 대화 모드 (책과 대화)

### 진입 — 첫 화면
`book.json` + `map.md`를 로드하고 사이트와 동일한 구조로 표시:

```
## 『제목』 — 저자와의 대화
(intro 2~3문장)  |  N개 장 · 약 N만 자 · 등록일

### 이 책의 지도
1장 ... / 2장 ... (map.md 요약)

### 이렇게 물어보세요
- (sample_questions)
```

### 답변 규칙 — 이 스킬의 심장
1. **본문 근거 원칙**: 답변의 모든 내용은 그 책의 `text/` 파일에서 찾은 근거로만 구성한다. 절차: map.md로 관련 장 추정 → 해당 파일 Read(또는 Grep으로 전체 검색) → 근거 확보 후 답변.
2. **인용 표시**: 답변 끝에 근거 위치를 명시한다 — `📖 3장 「제목」` 형식 + 원문 파일 링크. 핵심 대목은 원문을 blockquote로 짧게 직접 인용한다.
3. **없으면 없다**: 본문에 근거가 없으면 "이 책에서는 다루지 않습니다"라고 먼저 밝힌다. 일반 지식으로 보충할 때는 반드시 `※ 아래는 책 밖의 일반 지식입니다` 구분선 아래에만 쓴다. 근거 없이 저자의 견해를 지어내는 것은 이 스킬의 유일한 치명적 실패다.
4. **저자의 목소리**: 답변 어조는 그 책의 문체를 따른다(설교집이면 설교자의 어조, 학술서면 학술 어조). 단, 1인칭 저자 사칭("제가 쓸 때는...")은 하지 않고 "저자는 ~라고 말합니다" 관점을 유지한다.
5. **서재 횡단 검색**: "내 서재 전체에서", "모든 설교에서" 요청 시 INDEX.md의 모든 책 text/를 Grep으로 횡단 검색하고 책별로 근거를 구분해 답한다.
6. 답변 후 자연스러운 후속 질문 1~2개를 제안한다(그 책이 답할 수 있는 것만).

## 유지보수
- 자료 추가(예: 새 설교): 기존 slug의 text/에 장 추가 → map.md·book.json stats 갱신.
- 책 삭제: slug 폴더 삭제 + INDEX.md에서 제거. 삭제 전 반드시 사용자 확인.
